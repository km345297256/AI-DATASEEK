# 技能贡献模板

复制以下提纲填入贡献说明，使用 packages/tabular-quality 作为包目录结构模板。不要直接发布未替换标识和样例的副本。

- 包身份：`命名空间/名称`、精确语义版本、标题、作者、许可证。
- 流程分类：discovery / acquisition / quality / transformation / analysis / reporting 之一；领域独立填写。
- 解决的问题：适用场景、触发条件、不适用情况。
- 输入：文件标识或明确结构、格式、编码、单位与大小范围；禁止暴露宿主真实路径。
- 输出：可验证的文件或结构、来源摘要、方法及质量说明。
- 执行要求：所需已发布工具的精确版本；若使用平台沙箱执行脚本，明确运行前提及权限，不虚构依赖版本。
- 失败处理：输入错误、依赖缺失、超预算、外部失败时如何停止；不把阶段成功当整个任务完成。
- 样例：最小合成输入、手工可复算的预期值、失败输入；联网验证与离线测试分开记录。
- 验证证据：命令、环境、日期、实际结果、限制；格式检查不等于执行验证。
- 发布：包摘要、变更说明、新版本号；已发布内容只读。

最低目录：skill.yaml、SKILL.md、LICENSE。可选 scripts/ 和 references/ 应只包含发布必需的源码及小样例，不包含缓存、个人配置或输出产物。
