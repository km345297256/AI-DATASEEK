# 对话技能选择

聊天输入框“使用技能”菜单展示标题、分类、精确版本及验证状态，关键词支持标题、包标识、版本、领域与触发词。“添加技能”弹窗增加流程分类与搜索，并复用目录元数据展示。仅列出用户已添加的技能；自动启用技能继续由设置管理。

选择值始终保留技能的精确名称（包含包版本），不会将两个版本按标题合并。变更筛选不丢失已经选择的技能。目录标题用于阅读，不替换发送身份。

发送前，后端对显式选择做准入检查：不可用、未添加、同名身份不唯一，以及缺少摘要的版本包均返回 HTTP 409，不创建此次 Agent 执行。前端通过固定错误标识展示重新选择提示，不转发原始服务端正文，也不自动重试该错误。失效的自动启用偏好仍跳过；续传不重新选择技能。有效发布版本沿用已有 `name#sha256=...` 绑定机制，运行记录继续保留版本和摘要。

这一步只验证选择身份与安装资格，不宣称输入文件兼容性已检查，也不证明技能已经执行或科学方法已验证。后续仍需从会话输入到执行结果的完整样例验证。

验证覆盖：弹窗分类及标题检索、多个版本独立选择、筛选保持选择、无效选择在 Agent 调用前被拒绝、有效版本摘要绑定、失效自动偏好兼容，以及 SSE 错误不重试且不泄露原始错误正文。

回归结果：前端类型检查、构建及 2,676 项测试通过；后端 5,391 项通过、32 跳过、190 子测试通过，继续排除原有含导入时外部数据库操作的 test_admin_skill_delete.py。Compose 配置检查通过。沙箱仍因既有 PyMuPDF、python-pptx、原生 GRIB 依赖产生 3 项收集错误。

本地部署验证：当前构建首页正常；经前端代理发送不可用技能请求返回 HTTP 409 与固定错误标识。浏览器确认搜索、分类入口及未添加技能的空状态；未修改用户安装偏好或创建分析会话。
