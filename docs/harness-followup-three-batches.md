# Harness 后续借鉴：三批可靠性与效率改进

实施日期：2026-09-08。代码基线：`v2@3a16b01`。

## 范围与不变边界

保留 PlanActFlow / AgentLoop、FastAPI、原 SSE 事件结构、Cordis 工具治理及 Docker 数据集只读挂载。没有替换通信层，没有启用新 SubAgent / Code Mode 配置，没有使用真实模型或外部服务凭据进行测试。没有自动提交或推送。

## 第一批：断线恢复与预览稳定性

- 聊天流增加取消感知的有界退避、最新 `event_id/seq` 恢复。HTTP 200 不视为输入已接收；接收确认前保留同一 `client_message_id` 和请求内容快照，确认后以空消息继续接收事件。
- 网络恢复与业务失败分开。暂时断网不把已运行步骤标为执行失败；页面展示恢复状态，切换会话、停止或离开页面会终止旧连接。
- 文件预览使用作用域拥有的取消控制器与请求世代校验。旧请求成功、失败、解码完成和延迟布局都不能覆盖新文件；临时 HTML 资源按作用域释放。
- 回归包含真实 SSE 字节流的断开/回放，以及实际 Vue 组件 setup 的可控异步竞态，不仅检查源码字符串。

## 第二批：长历史、大文件与产物效率

### 历史与界面

新增 `GET /sessions/{id}/history?turns=5&before_seq=...`，保留原完整历史接口。新版会话通过序号和用户轮次索引加载最近 5 个完整轮次，固定本页上水位，历史页面不混入读取期间新产生的事件。旧混合序号历史仍走原兼容投影。

聊天与数据集探查页可加载更早内容；历史独立投影后插入，不重建当前实时消息、工具审批或恢复游标。稳定消息 key 避免前插历史导致当前组件重新挂载；自动滚动不再深度监听全部消息对象。

**限制**：这是完整轮次分页，不是任意单轮的硬字节/事件上限。超长单轮仍完整读取，避免截断计划或工具调用/结果。用户不断主动加载旧页时，累计消息仍会增长；本轮没有宣称已完成完整虚拟列表或持久有界会话投影。

持久调度路径仅读取一次执行历史快照，按当前输入序号隔离后续输入，并让前置判定和 PlanActFlow 复用；无快照的旧调用方式仍可读取原历史。这里消除重复查询，尚未让执行历史总读取量与会话长度完全无关。

### 文件预览

新增 `GET /files/{opaque_id}/preview`，复用现有存储真实范围读取：

- 文本每次最多 64 KiB，UTF-8 边界连续。
- CSV 每次最多 128 KiB，每页最多 100 条数据、50 列，按完整记录推进，支持多行引号、转义引号、字面引号、BOM、CRLF、空白页后的表头。
- 版本变化拒绝混页；不支持范围读取时明确提示，不退化成隐藏的完整下载。
- 只保留当前页内容及历史偏移，原完整下载入口保留。单条 CSV 记录超限或编码不支持时明确提示。
- 仍校验文件归属和私有 Spill 类型；不返回宿主机路径。

### 产物同步

沙箱增加内部只读内容指纹接口，针对已知输出先在沙箱本地计算 SHA-256。未变化的产物无需传到后端；变化和新产物仍走原交付流程，同大小覆盖仍能识别。旧沙箱无该接口时保留原兼容方式，未声明图表的发现逻辑不变。

扫描范围限于输出目录；不跟随符号链接、不读设备/FIFO。哈希按初始大小加 1 字节封顶、分块读取，具有批次期限与协作取消；读后重新从根目录验证路径身份，防止父目录替换返回旧指纹。该机制减少跨容器传输，但仍需沙箱本地读取文件计算哈希，不把它描述为零磁盘 I/O。

### 上下文准备与可观测性

Token 估算按消息贡献增量更新，工具 Schema 每次请求只估算一次；缓存只在单次请求内部存在，不跨会话保留敏感正文。保护上下文、完整工具交换、HMAC 及压缩记录语义不变。

模型追踪增加内存变更落库、上下文准备、请求身份、准入审计、模型调用、用量结算的分段耗时。计时是本地单调时钟，不是模型首 Token 延迟，也不包含所有后台落库耗时。

## 第三批：持久输入调度与异常恢复

输入接受状态与用户事件写入同一 Mongo 文档；私有状态不进入 SSE 或浏览器数据。Redis 继续负责唤醒和实时传输，不再作为输入是否已被可靠接受的唯一依据。

状态为 `pending → claimed → running → completed`，异常收敛到 `cancelled/interrupted`。原子版本条件及每会话唯一活动输入约束防止两个调度器重复领取；租约维护与准备工作分开。

- 未开始执行的输入可以在异常后重新调度，准备重试有次数限制。
- 已进入执行的输入租约失效后只标记中断，不自动重放未知副作用。
- 终态事件与输入有稳定的私有关联，修复“终态已存、状态尚未结算”的窗口。
- 事件先持久化再发布；继续兼容旧 `event_id` 客户端与新版序号恢复。
- 重复提交立即附着已有输入；当前进程暂时没有 Task 时仍可等待持久事件，不因恢复租约尚未到期而提前断开。
- 当前输入不会被上一轮迟到终态错误关闭；取消、删除与授权撤销均有专门检查。

**没有实现任意 AnalysisJob 的检查点续算**。现有领域工具没有统一检查点协议；自动重跑 shell 或其他有副作用操作不安全。后续应选择明确支持检查点的计算工具单独试点，而不是放大超时或自动重放。

运行中服务只读抽检通过：

- 5 个已有已完成会话，分页投影与原完整历史逐项对照一致，其中实际加载了 3 页更早历史。

本轮没有发送真实模型请求，也没有对现有会话新增分析任务。以上回归与抽检不能替代所有领域的端到端实测，尤其尚未进行高并发持久事件轮询压测、通用 Job 检查点续算或超长单轮硬上限验证。
