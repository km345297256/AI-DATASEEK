# 2026-10-20 改动说明

## 范围

- 分支：`v2`；本批基于 `a9eaccd`。
- 本次只检查、记录并提交代码，不部署、迁移或重启生产服务。
- 排除真实环境文件、密钥、数据集、运行输出、测试缓存及本地重复备份。

## 主要改动

### 1. 文件写入进度与已保存版本复用

- 新增请求内的 `ArtifactWriteProgress`，区分保存内容、获取新输入证据、执行程序和交付文件等阶段。
- 识别重复覆盖、重复追加／替换及已提交源码版本，引导复用、执行、检查或完成已保存内容，减少没有新证据的反复重写。
- 不增加耗时、工具次数或版本次数配额；不同的有效分块追加和补丁仍可继续。
- 使用私有内容身份记录状态，不保存源码正文；已提交版本不等同于沙箱当前字节，也不代表执行成功或内容审核通过。
- Agent、文件工具、进度恢复及协议恢复同步接入，补充真实调用流程和重复修订回归测试。

### 2. Shell 源码写入与执行识别

- 扩展保守的 Shell 准备／执行识别，处理可识别的源码与报告写入形式、引用、重定向和 heredoc 数据。
- 引导通过受控文件工具写入、通过现有程序执行流程运行已保存程序，区分准备动作与真实执行结果。
- 识别器不执行或展开 Shell 内容，不将动态表达式解析为新权限；它不是完整 Shell 安全解析器，未知表达式仍由既有授权和隔离机制处理。
- 加强执行来源与终态身份测试，避免改变调用编号、措辞或重复提交相同源码被当作新的修复证据。

### 3. 程序失败后的受控诊断

- 新增诊断计划器，基于当前可信失败回执、启动源码快照和已绑定输入安排只读检查。
- 对同一失败原因与输入组合不重复安排相同诊断；不同的已确认失败或输入变化可重新检查。
- 诊断读取必须经过现有工具注册、授权、事件和结算流程；权限拒绝、读取失败或取消不计为分析进展。
- 限制输入样本数量与源码上下文范围，不扩大数据访问范围，不把诊断计划等同于观察结果或执行成功。

### 4. SSE 终态与停止观察

- Redis 暂未提供消息时，可从持久历史补读已落盘事件，以覆盖终态提交成功但通知缺失的情形。
- 终态仍需匹配当前输入身份，并按序号去重；不因历史查询失败伪造“已完成”。
- 前端按每条连接记录结束状态，收到有效终态后清理提示并关闭对应连接，忽略迟到的网络回调。
- 停止观察、历史恢复和会话切换逻辑同步完善，避免旧终态阻止取消当前工作或终态之后重新显示连接错误。
- 更新消息和工具时间线展示，补充传输层、停止流程及持久终态回归测试。
