# 任务进度状态与滚动区域焦点样式

## 原因

原 PlanPanel 在没有 running/pending 步骤时固定显示“任务已完成”，但图标
独立依据 failed 状态显示红叉，计数又将所有终态算为完成。会话 completed
只代表执行已结束，不能据此认定所有成果与说明均成功。

整页蓝色边框来自可聚焦的 SimpleBar 滚动区域的浏览器默认 outline。

## 修改

- 用同一展示函数驱动折叠标题、图标、展开行和成功步骤计数。
- 匹配当前用户轮次及 step_id 的结构化 analysis_outcome，区分全部完成、
  部分完成、失败、停止与执行中；不能把上一轮结果移到新任务。
- 部分完成显示琥珀提示，而非“红叉＋任务已完成”；失败步骤不计入成功数。
- 普通分析页与只读分享/回放页使用相同展示规则。不改后端结果或历史记录。
- 只移除滚动区域自身的默认外框；保留 Tab、PageDown 与内部按钮焦点指示。
  键盘聚焦滚动区域时使用低对比度的内部细线，不全局禁用焦点样式。

## 验证

- 新增 10 项状态与实际会话控制器、Vue 组件回归。
- 离线真实浏览器覆盖 8 种任务状态，320/390/768/1200 像素下鼠标焦点、
  Tab、PageDown、内部按钮焦点、横向溢出；无真实 API 或模型请求。
- 前端类型检查、生产构建及全部测试通过；后端 5,922 passed / 30 skipped，
  Linux 沙箱 5,834 passed / 87 skipped；Compose 和 diff 检查通过。
