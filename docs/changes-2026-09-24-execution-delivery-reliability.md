# 分析执行与成果交付可靠性（2026-09-24）

## 本轮定位

- 固定成果目录未在首次执行前由平台准备，文档提取脚本可能因输出目录不存在而失败。
- 通用工具集只先提供文档元数据检查，而且检查结果错误地声明可直接答复；已有 PDF/DOCX 正文提取能力没有优先暴露。
- 程序错误文本或源码版本变化容易掩盖同一阶段没有进展；反之，已经完整读取的小文件也不能因为没有“新内容”而失去正常诊断机会。
- 原审核协议在同一响应里构建正文、编号和自评科学性，且格式修复时额外要求字段，导致有效结果因协议不稳定被拦截。
- 成果契约识别 SVG 图像，但沙箱验收器只支持位图，造成真实 SVG 被标为不支持格式。缺失附件是另一种状态，不应混同处理。
- 界面没有区分历史执行失败与同一步骤内确认恢复。

## 通用修复边界

1. 平台只准备可信工作区下的固定 `output` 目录；禁止符号链接、验证可写性；任意输入目录和缺失工作目录不自动创建。只读预检保持只读，启动前失败保持“未启动”。
2. 通用模式提供已有 PDF/DOCX 正文提取工具，元数据检查不再冒充内容证据；自定义脚本仍用于现有工具无法覆盖的分析。
3. 失败诊断按程序、实际执行版本、原输入和错误证据管理，不引入任务总次数、总时长或消耗限额。未知执行不自动重放，写入和改名不等于进展。
4. 分离“有据正文构建”和“冻结候选核验”：先完成引文纠错及公开路径处理，再由主机编号并独立核验科学性和原问题覆盖。只读格式恢复使用相同输入和相同根结构，不要求新分析。审核协议恢复也不产生重执行权限。
5. 增加安全 SVG 结构及离线渲染验收，并用跨服务格式契约测试防止分类与验收能力再次失配。文件存在性、内容安全、上传字节摘要仍独立验证；不把缺文件或损坏文件标成完成。
6. 仅依据信任执行账本生成不含路径的展示标识；同一步骤同一程序及参数后续确认成功时，先前记录显示“执行失败，后续已恢复”。保留失败详情，不改变整项任务或成果的真实状态。

## 不做的事情

- 不增加任务消耗额度限制，不重跑或改写旧分析任务。
- 不向模型发送用户数据作为本轮回归输入。
- 不放宽数据集只读挂载与宿主路径边界。
- 不把正文协议错误当科学性否定，也不把文件验收成功当科学结论正确。

回归覆盖真实本地沙箱执行、文档工具、生成的 Matplotlib SVG、恶意/空白 SVG、精确字节交付、连续不同执行错误、冻结审核协议、历史解释来源、事件回放及前端恢复状态。
