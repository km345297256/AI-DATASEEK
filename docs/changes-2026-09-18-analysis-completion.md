# 分析完整交付与恢复（2026-09-18）

## 目标及边界

按任务完成条件推进分析，不能把一次请求超时、暂时的核验连接故障或证据引用格式问题直接当作计算失败。不能用隐藏提示、删掉需求或放宽真实性检查的方式制造成功。任务累计工具次数、token、调用次数和总时长继续不设额度。

输入不存在、需要用户授权、用户取消、执行状态无法确认等情况不是“无限重跑”可以解决的问题。系统必须保留已验证成果，并具体说明阻塞原因；不猜测不存在的数据，也不重复执行状态不明的有副作用操作。

## 排查依据

详见 `analysis-completion-forensics-2026-09-18.md`。用户引用的缺一张表来自故意缺列的合成验收；缺列本身不应伪造完成，但生产版本错误丢失具体原因。另两条可完成任务的文件正确、最终审核失败。取证确认运行容器未包含工作区的部分证据恢复修复，不能把源码存在等同于服务生效。

## 本次恢复路径

- **结果整理**：单个模型请求的超时进入现有传输重试。外层保护覆盖完整请求重试、退避及审计存储，不再提前取消第一次请求。重试不启用工具，不重跑已完成的分析；真实取消仍立即传播。
- **审核引用**：对已存在成功非纯写入观测的要求检查，允许基于冻结证据纠正错误证据类型或重新核对不确定项。已验证段落不可被改写；复核仍不确定时不得改称成功或“确认未执行”，也不能因此取得重跑授权。
- **文件核验**：连接中断、请求超时和暂时 HTTP 服务故障只重试相同的只读校验接口。内容无效、权限错误、协议错误不重试；不回退为“存在即有效”，不要求模型重新生成文件。取消不被转换为校验失败。
- **原始证据**：交付补齐前保留原始观测快照；如果工作副本后来变化，原上传文件及其说明仍只能依据原版本的证据。已执行源码关联必须来自私有执行账本，不能相信公共回包中自报的执行信息。
- **长时间计算**：第一方 `program_run` 的总进程运行上限改为分段观测；启动一次、观察同一操作，最终退出前保持作业运行状态。单次网络请求仍有保护，用户取消仍可停止进程。同名插件及普通工具不得借此绕过其操作超时。作业总时限为 `None`，租约续租和失租取消仍有效。

## 验收要求

1. 注入“先超时、后恢复”，确认分析只执行一次、文件不被重写、最终核验使用实际输出。
2. 对错误引用、不确定引用、失败观测、伪造执行收据、跨步骤源码版本及取消分别做正反例。
3. 长程序跨过原等待窗口仍能结束；轮询故障不触发再次启动；取消只清理同一进程一次；插件不能伪装成长分析豁免。
4. 缺列场景保留真实 CSV 和明确缺列说明；不存在的第二份结果不得生成或计为成功。
5. 完整后端、前端、沙箱回归及 Compose 配置检查通过，再用 `run.sh` 更新现有本机同一栈。不得中断正在运行的用户分析、重跑旧任务或增加公网端口。
