# 执行可靠性、模型输入优化与离线评测更新

日期：2026-09-15；分支：`v2`；对比基线：`9b95762b601455939e21e1077c35d0aa980dc0a6`。

## 1. MCP 协议与任务准备可靠性

- 正确处理 MCP `isError`、文本与 `structuredContent`，不把结构化返回提升为执行授权或产物凭证；二进制内容不以对象字符串混入模型上下文。
- 工具发现分页有界、原子发布，拒绝重复游标和重名工具。发现时固定输入／输出契约，调用期间不隐式重新发现；校验不下载远程 Schema 引用。
- HTTP/SSE 与 streamable HTTP 发现、调用均保留配置请求头，并继续走原有凭据脱敏与 spill 路径。
- 任务准备失败或取消时，由创建工厂注销、关闭未启动任务，并通过 CAS 管理会话任务指针和数据集选择，避免覆盖后继任务。
- 回滚不销毁复用中的会话沙箱或页面；没有精确解绑能力的沙箱观测关联不盲目清空。

## 2. 增量执行历史

新增私有 `ExecutionHistory` 投影及 Mongo 缓存，按当前输入的事件序号读取严格历史前缀，隔离后续排队输入。保留最近对话、最新计划、视觉与分析结果、spill 引用和完整解包证据，并将当前输入放入任务私有副本。

缓存命中后只分批读取新增事件正文，每批 256 条；通过版本、序号与事件数检查发现迟到事件时重建。超过 4 MiB 不持久化缓存，不为命中率裁剪证据。旧混合序号历史及安全续作保留兼容路径。

收益是减少历史正文传输、解码和重复投影。前缀计数仍有索引扫描成本，不宣称整体 O(1)，也没有删除历史或向浏览器开放缓存。

## 3. 图片输入和模型请求保护

- 新增 Pillow 依赖，对模型侧图片副本做安全解码、方向处理、尺寸限制和 PNG 编码；存储原图、下载及页面预览不变，不静默丢弃多帧内容。
- 沙箱下载增加兼容的可选 `max_bytes`，设置后流式限量读取。
- 默认单请求限制：16 张图、单源文件 32 MiB、解码 4000 万像素、模型副本长边 2048、data URL 合计 20 MiB；通过 `VISION_MAX_*` 配置调整。这些不是任务累计额度。
- 私有记忆保留可重新鉴权的文件引用，发送前展开为模型副本；优先为本轮图片预留容量，旧图不可用或超出余量时使用明确占位，不把私有引用传给模型。
- `MODEL_REQUEST_CAPABILITIES` 按实际 provider 和精确模型名声明能力；未知模型保持保守预算，不根据名称猜测，不自动更换模型、密钥或启用特定图片 Token 算法。

## 4. 重试和工具契约准备缓存

- 合法且不超过本地上限的 `Retry-After` 优先；合法但过长的等待停止自动重试，缺失、畸形或过期值使用有上限的指数退避和抖动。
- 余额／计费耗尽、参数错误不重试；等待可取消，不重放已经执行的工具。重试决策记录在已有失败追踪的私有字段，不扩展公开 API；审计失败不会触发额外模型请求。
- 契约缓存限定当前任务管线，最多 128 项、源 Schema 合计 1 MiB、单 Schema 64 KiB。内容或模型元数据改变时失效，无法证明稳定时旁路。
- 只缓存成功准备的校验器，每次仍执行参数校验、自定义验证和默认值工厂；不缓存业务参数、执行结果或错误。

本轮在既有 Agent／PlanActFlow 内改进实现，保留 FastAPI、Cordis、Vue、API/SSE、Docker 数据隔离与只读路径边界，不替换 AgentLoop 架构、不恢复任务累计调用／Token／时长配额。
