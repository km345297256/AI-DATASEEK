# 2026-09-29 Harness 增量改进

基于上轮对 DeepSeek Harness `4878cdabd87d4041bdaff61d04c966883b9fd07a`
（2026-09-28，0.2.0-rc.1）的审查，落实适合 DataSeek 的五项建议。
不迁移产品形态，不切换模型接口，不增加权限或任务配额，不修改生产 UI 模板/CSS。

## 实施范围

1. **工具批次中断收尾**：逐调用保存安全的 ToolMessage，再对外发出完成事件。
   已完成结果不会因同批后续调用中断而丢失；尚未进入调用与结果未知分开处理，
   结合现有执行账本判定，不把 CALLING 展示事件当作实际执行证据。不自动重放工具。
   消费端关闭、取消与保存失败路径纳入回归；等待用户输入的继续对话保持兼容。
   在 WAIT/DONE/ERROR 发布前完成工具收尾，避免先结束输入租约再补结果；沿用现有
   所有者校验保护新增保存边界。正常关闭期间新收到的取消继续向上传播，收尾发布有超时。
   新格式将用户回答作为新输入，保留已保存的工具回执，并兼容旧格式的未闭合提问调用。
2. **配置目录竞态**：共享目录采用请求/选择世代和同世代请求复用；保存后强制刷新。
   旧响应不能清除新选择，查询失败保留最后成功状态，新的成功查询仍能确认真实删除。
   测试验证乱序响应之后真正发送分析请求仍携带用户选择的配置 ID。
3. **独立持久化协议**：原六个根不变，新增七个独立根，记录真实版本及所属持久化入口。
   新增真实生产绑定的 AnswerReviewMarker；旧 MCP 消息冻结完整 key/占位文本并回读。
   只追加新快照，不覆盖历史。详见 [持久化门禁](persistence/README.md)。
4. **模型缓存观测**：私有记录加入可选缓存读取/写入计数及实际请求工具 schema 的摘要/数量。
   缺失、冲突或非法缓存数据为未知，不是零；DeepSeek 未命中数不是缓存写入量。
   原 prompt/completion/total 用量和计费/配额语义不变，不保存原始 metadata 或工具 schema，
   不扩展现有公开 trace 接口与 UI。未实施新的 Messages API 或更换模型。
5. **浏览器回归入口**：统一门禁纳入四组 Chromium 与两组 WebKit 场景。
   覆盖输入/布局、追问结果、任务状态、原 ID 恢复、已接收输入只读回放、迟到响应、历史和图片锚点。
   缺依赖明确失败，不静默跳过。详见 [浏览器门禁](frontend-browser-gate.md)。

## 验证边界

使用合成数据、模拟模型响应和隔离浏览器 HTTP fixture；未调用真实模型或访问用户数据集。
浏览器用例不启动监听端口，不访问运行中的应用。WebKit 的输入法用例覆盖浏览器组合输入事件，
不声称自动操作了操作系统输入法；局部布局 fixture 保留已有消息组件替身，不能代替整站逐页验收。
AnswerReviewMarker 约束稳定信封，内部扩展诊断仍需科学核验行为测试，结构通过不等于事实获证。
工具收尾是同一次执行的结果保存/事件补全，不是重试执行。若持久化服务完全不可用，仍不能
承诺落盘成功：保留原异常和进程内观察，只记录异常类型诊断。所有者检查沿用现有机制，
不是新增跨库原子 fencing。WAIT 测试使用实际 ExecutionAgent 和模拟的租约完成边界；
另行验证实际 runner 发布入口拒绝失租写入，不将这些测试等同于 Mongo/Redis 端到端测试。
