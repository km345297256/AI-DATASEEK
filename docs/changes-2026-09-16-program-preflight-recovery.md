# 启动前纠错恢复与回答核验超时

## 本次问题与边界

用户新分析在保存代码后结束，仍缺图表。检查对应执行记录确认：第一次
`program_run` 时目录和脚本尚不存在，私有操作回执随后确认 `not_started`；
创建目录、写入脚本后，再次运行相同参数被通用重复失败规则拦截。此前参数
Schema 的修复并未覆盖这个状态转换，直接工具烟测也没有走完整 Agent 防循环链。

修复针对所有受支持的保存程序执行，不根据数据集名、文件名、字段或科学分析
方法分支。不重新引入任务累计工具、时间、令牌额度；不迁移或重跑用户旧任务。
保留数据集只读挂载、宿主路径 allowlist、真实副作用未知时不自动重放的边界。

## 通用恢复证据

- 新增沙箱私有只读 `program-preflight`：检查工作目录可访问性、源码普通文件
  类型、读取权限和完整源码摘要；不执行代码，不创建操作回执，不返回源码或路径。
- 两次 no-follow 文件系统观察防止链接和读取竞争。时间戳、inode、调用编号不
  参与前置条件摘要；相同内容重写、目录列表成功不算修复。
- 只有“原调用独立确认未启动、原前置状态有可信基线、当前前置条件发生改变且
  已可运行”才允许相同参数的纠正尝试。目录或权限修复同样有效，不要求改代码。
- 未知或失效的当前观察不借用旧 ready 状态，旧 `not_started` 回执不能豁免
  后来的未知操作。恢复只影响对应程序/调用，不能清空其他程序错误。

这项实测不记为完整通过。

## 核验传输修复

- 核验专用单次模型请求等待由 `ANSWER_REVIEW_REQUEST_TIMEOUT_SECONDS` 配置，
  默认 60 秒；不是任务累计额度。截止在模型物理请求审计边界内部实施，使自身
  超时明确记录为 `provider_timeout`，而非误记为用户取消。
- 临时超时使用现有只读模型重试政策；每次真实请求和计划重试有独立 trace。
  不调用分析工具、不重写脚本、不重跑绘图、不将未核验回答直接视为成功。
- 首轮回答核验与引用纠正各自的外层等待覆盖完整请求尝试、退避及审计 IO，
  不再被外层固定 45 秒抢先取消。最终超时有明确 `review_timeout` 诊断。
- 用户取消仍直接传播且不重试。其他模型角色默认不设置此专用请求超时，
  不更改模型、思考模式、温度或全局输出上限。证据和引用校验规则保持不变。
