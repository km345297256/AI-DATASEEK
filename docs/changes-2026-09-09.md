## 一、分析成果验收与安全续作

### 从“流程结束”改为“实际交付验收”

- 前置决策和计划保留用户要求的图片、表格、报告、代码等成果类型、数量及格式，多步骤重规划不能降低任务级要求。
- 新增成果清单、内容验证和上传字节核对：检查真实格式、文件大小、SHA-256 及必需成果是否齐全，不能用一个脚本冒充已生成的图表。
- 消息增加 `metadata.analysis_outcome`，明确区分成功、部分完成、失败，并显示逐文件问题及缺失项；流程终态不再等同于业务成功。
- 必需成果的内容问题可以进入有进展检查的局部修复；有效成果保留。仅上传失败时优先重新交付，不要求模型重新计算。可选文件问题不阻断已满足的必需成果。
- 诊断审计保存在服务端，公开消息只包含安全文件名、受控原因和状态，不传递私有路径或原始验证回包。

### 在证据充分时继续未完成部分

- 新增私有检查点，绑定原目标、配置、输入身份、完成步骤、数据与成果内容指纹。
- 有效期内由用户触发同会话续作；重复提交、跨身份领取、来源变化、后续新输入均有校验和并发保护。
- 已完成步骤不重算；只有交付失败时可补验证和上传。不自动重放执行状态未知或不能证明可重放的操作。
- 这不是任意程序指令级断点恢复：当前检查点面向具有完整指纹的数据集分析，带新附件或超出快照边界的任务不承诺可续作。

主要实现：`analysis_completion.py`、`analysis_artifact_repair.py`、`analysis_checkpoint.py`、`analysis_delivery_audit.py`、沙箱成果验证服务及前端 `AnalysisOutcomeNotice.vue`。

## 二、工具合同、执行证据与无进展保护

- 内置、插件、MCP 和 Code Mode 内部工具在治理、作业和执行之前统一验证真实参数 schema；参数错误反馈只包含字段和错误类型，不回显敏感参数值。
- 工具异常统一为失败状态。只有明确保证尚未执行或同请求幂等的瞬时失败才允许安全重试，网络错误本身不能作为重放证据。
- Shell 增加私有操作身份、命令摘要、进程代次、退出码与进程组状态凭据；查询、等待和取消绑定原操作，避免误操作复用名称的新进程。
- 新增重复读取、失败写入、无执行反馈的重复代码草稿等无进展检测；中间过程显示单条瞬时进度，不连续追加状态段落。
- 生产分析取消累计工具轮次、模型调用数、Token 和总时长额度；仍保留计量审计、上下文容量、单次操作超时、取消及资源安全边界。旧累计额度环境变量不能重新启用这些限制。
- 核心 `file_read` 与 `file_find_in_content` 不再接受 `sudo=true`，使只读合同与真实执行行为一致。

注意：取消累计额度可能增加长任务的模型费用；不代表取消服务商余额、速率限制或上下文限制，也不代表任务可以忽略未知副作用继续执行。

## 三、输入持久化与 SSE 断线恢复

- 输入接受与用户事件采用持久记录；Redis 继续用于唤醒及实时传输，不再是判断输入是否可靠接受的唯一依据。
- 输入领取使用原子版本条件、每会话活动输入约束和租约，避免并发调度重复执行；运行中失联的任务保守标为中断，不自动重跑未知操作。
- 前端按 `event_id/seq` 有界退避恢复。输入未确认前重用同一 `client_message_id` 及内容快照，确认后只恢复事件接收。
- 切换会话、离开页面或停止时取消旧连接；暂时断网与真实执行失败分别展示。终态先持久化再发布，并与对应输入关联。

保留现有 SSE 结构和 PlanActFlow，没有引入新通信层或替换 AgentLoop。

## 四、长会话、大文件与上下文效率

| 场景 | 本轮变化 | 适用边界 |
| --- | --- | --- |
| 长会话 | 新增完整轮次历史分页，默认最近 5 轮；按固定上水位读取，更早历史独立前插 | 保留旧完整历史接口；超长单轮仍完整读取，不宣称已实现全量虚拟列表 |
| 文本预览 | 范围读取，每页最多 64 KiB | 校验 UTF-8 连续边界和文件版本；完整下载仍保留 |
| CSV 预览 | 每页最多 128 KiB、100 条数据、50 列；按完整记录推进 | 保留多行引号等记录语义；超限或不支持编码明确提示，不偷偷全量下载 |
| 文件切换 | 请求取消、世代校验、组件作用域资源回收 | 迟到的成功、错误、解码和布局结果不覆盖当前文件 |
| 成果同步 | 沙箱先计算已知成果指纹，未变化文件跳过传输 | 仍需沙箱本地读取哈希，不等于零磁盘 I/O |
| 上下文准备 | 增量更新消息 Token 估算、单请求内复用工具 schema 估算及历史快照 | 保留完整工具交换和可追溯压缩；不建立跨会话正文缓存 |
| 模型追踪 | 增加上下文准备、准入、调用与结算等分段耗时 | 不是首 Token 延迟，也不是端到端任务提速承诺 |

## 五、Cordis 声明式可视化插件

### 使用与架构

- 将文件格式匹配、读取器、视图适配器和个人启停状态分离；同一格式可选择多个视图。
- 可视化采用独立 Cordis Context、fiber、revision 与原子目录重载，不进入 Agent 工具列表；个人开关不销毁共享插件实例。
- 新增可视化目录、状态管理和按授权 file ID 读取科学预览的接口。偏好按服务端身份存储，无登录本机部署显示共享配置。
- 插件页增加可视化管理；文件面板使用统一 `VisualizationHost`，支持视图选择、启停响应和旧请求清理。
- 声明文件位于 `plugin-host/visualizations/`，仅允许受审查的读取器和前端适配器，不接受任意脚本入口、模块 URL 或用户代码上传。

### 14 个内置视图

- 原有场景：图片、TIFF、Shapefile、分子/晶体、OBJ、HTML、Markdown、文本、CSV。
- 新科学场景：NetCDF 地图与曲线、FITS 图像与曲线、FASTQ 质量采样。
- 科学视图可选择变量、维度切片或 HDU；NetCDF 地图可使用随包发布的离线地理轮廓，不向地图服务上传数据坐标。

科学读取运行在现有沙箱镜像的一次性隔离容器：无网络、无端口、无宿主目录挂载、非 root、只读根目录，以及明确的内存、CPU、进程、输入输出和执行期限限制。Docker 不可用时不降级到后端主进程解析。

当前是有界文件/切片预览：NetCDF/FITS 输入最大 64 MiB，FASTQ 只支持未压缩四行记录的前缀采样；不承诺任意大文件、完整 GIS/WCS 或全量测序质控。共享页面保留已有签名文件预览，新科学读取暂不开放共享入口。
