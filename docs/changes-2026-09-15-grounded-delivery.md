# 分析回答与成果交付的一致性修复

## 问题与边界

旧流程把「至少交付一张图」当作成功的充分条件。最低数量满足后，模型在最终回答中虚构的附件和分析方法可能仍被原样发布；文件校验虽然拦截下载，却把缺失文件显示为不影响成果的附加问题。

本次修复针对通用执行和交付边界，不包含任何数据集、文件名或分析方法特例。不迁移或重跑历史任务，不恢复任务工具调用、令牌或累计耗时额度。只保留已有安全边界、无进展停止机制以及独立模型请求的超时/瞬时网络重试。

## 新流程

1. 执行前契约保留成果类型/数量/格式，并可记录明确分析目标 `objective` 和承诺的精确输出路径 `output_paths`。前置决策和计划合并不能把不同分析目标压缩成同一个数量名额；执行器最终答案不能自行增加契约。
2. 文件内容校验、上传大小和 SHA-256 绑定保持不变。命名成果必须由准确路径上的有效上传满足，不用其他同名或同类型文件代替。
3. 交付前对成功分支也进行独立、无工具的回答证据审核。审核输入只包含任务范围、模型草稿、带步骤标识的工具观察、已验证文件清单和注册元数据。草稿不是证据；文件存在不等于其中分析结论正确；保存脚本不等于执行脚本。
4. 审核输出按段提供证据身份和原文摘录。服务器检查引用确实存在、操作状态和来源角色适用、文件身份准确、必需分析目标全部受审。审核失败保留已验证文件，不回退发布草稿，不要求模型重跑原任务。
5. 只对原始契约中确认未完成的目标安排新的局部操作。已验证上传不可修改；内容不符合目标的命名工作副本可以在确认证据、版本记录和无进展控制下修正。仅改文件哈希、重命名或重新声称成功不能取得额外尝试。
6. 纯模型虚构、没有实际尝试记录的附加文件声明在纠正后不再显示为用户文件故障；完整失败收据仍保存在私有交付审计。真实尝试失败、路径冲突、证据截断或不明来源的文件问题仍保留。
7. 公开 StepEvent 副本、计划、附件和最终总结采用同一已核验结果。后续总结不再重新编写科学事实。后续追问可引用带新版审核标记、范围相符的历史结果，但历史结果不能证明执行了新的计算。

## 安全与可观测性

- 读写数据集边界、宿主机路径 allowlist 不变。目标说明禁止绝对路径；公开 outcome 仅包含类型/数量/安全名称，不包含私有目标或路径。
- 未知执行状态不能触发自动重放。审核过程不携带工具、执行器聊天记忆或模型 JSON 修复器。
- 段落的科学语义由独立模型审核判断，不能声称程序形式化证明了所有科学结论。确定性检查负责来源、引用、文件身份、状态和发布边界。
- 证据上下文有明确的裁剪标记；缺失或截断不能作为「尚未执行」的自动补全依据。这是审核输入的资源边界，不是分析任务额度。
- 新增 `analysis_answer_review` 日志和 `step.outputs.answer_review` 安全摘要；模型调用角色为 `answer_review`。仅网络瞬时失败按现有策略重试，不重复分析。
- 新增原因 `answer_validation_unavailable`、`analytical_requirements_missing`；前端不再对任意附加问题笼统宣称「不影响成果」。

## 验证

- 新增契约精确身份、审核器、真实 runner/flow 交付边界、语义工作副本替换测试。
- 覆盖虚构附件/未执行分析、同名不同路径、已满足最低图数、真正辅助文件错误、审核不可用、公开事件副本、后续总结、追问、无进展和只读边界。
- 前端类型检查与生产构建通过；前端全量测试 2652 项通过。
- 沙箱完整测试 5785 项通过、87 项跳过；参考解析库仅安装在一次性测试容器，不改变生产沙箱镜像。
- 最终冻结源码的后端全量测试 5634 项通过、32 项跳过；关键交付/终态集成测试 89 项通过。另在后端生产依赖的一次性容器完成全量回归。
- `backend/scripts/smoke_analysis_answer_review.py --live` 为显式开启的纯模拟模型冒烟测试，不读取数据集、不创建会话、不执行分析工具；真实 DeepSeek 已验证能移除不存在的附件和无证据结论并保留测量结果。

服务通过唯一 Compose 栈和 `./run.sh` 更新，保留本机 `127.0.0.1:7001`，不变更公网部署。更新前确认没有运行中任务；仅更新后端和前端，未重跑或改写历史分析，数据库和原始数据保持不变。空闲临时沙箱仍受服务既有生命周期管理，不作为持久化成果存储。

部署后首页及 `/api/v1/datasets` 均返回 HTTP 200，五个关键后端模块的容器哈希与最终本地源码一致。
