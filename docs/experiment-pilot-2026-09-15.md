# DataSeek 首批对比预实验报告

日期：2026-09-15。实验标识：`pilot-20260915-six`。用途：论文实验的流程校准与问题定位。

**获批的 6 次分析已全部执行，独立验收通过 5 次：DataSeek 默认流程为 2/3，通用 ReAct 为 3/3。** DataSeek 的 Iris 任务因路由误判进入文件预览流程，未交付要求的 JSON；产品也明确报告了失败。三个开发样例、每种方法各一次，不能支持系统优劣、显著性或成本优势结论。

## 1. 本轮完成的工作

- 建立独立评测入口，覆盖任务冻结、数据身份核验、两种方法运行、实际成果下载、客观评分、运行汇总与用量核对。
- 为 18 份内置公开样例生成 36 道结构/分析题，覆盖九个领域。标准答案由独立计算产生，保留在评测器私有侧。
- 从中选定三个不同格式的分析任务，按固定打乱顺序运行 DataSeek 与通用 ReAct，共六次；没有失败重跑或第七次分析。
- 保存原始记录、实际输出文件、评分细项、运行配置、数据哈希和诊断证据。三次基线运行创建的临时沙箱均已确认清理；DataSeek 实验会话保留供检查。

这批数据参与过产品开发，全部归为开发预实验。36 题是已准备的题库规模；本轮实际只测试其中 3 题，不能写成“九领域验证完成”。

## 2. 方法与评分口径

| 项目 | D：DataSeek 默认流程 | B1：通用 ReAct |
| --- | --- | --- |
| 基础模型 | 现有 DeepSeek 服务，`deepseek-flash` | 同一模型服务与别名 |
| 模型参数 | temperature 0.7；普通阶段最大输出 2,000，执行阶段 4,096 | temperature 0.7；每次最大输出 4,096 |
| 执行方式 | 真实产品入口，新建独立会话；`general/on_demand` | 独立观察—调用工具—观察循环，仅暴露 Shell 与文本读取工具 |
| 科学环境 | 现有科学沙箱、原始数据只读挂载 | 同一科学镜像、同一数据挂载校验 |
| 专用机制 | 保留工具发现、探查、Spill、AnalysisJob、交付检查；Code Mode 与领域 SubAgent 关闭 | 不主动装入专用科学工具目录、产品规划与交付修复；复用部分公共工具保护 |
| 资源控制 | 300 秒分析墙钟取消；缺少逐请求累计 Token/调用数准入 | 300 秒分析墙钟；200,000 Token 估算准入、64 次物理请求上限 |
| 输出验收 | 下载实际交付的 `answer.json` | 从实际沙箱文件收集 `answer.json` |

两组读取相同原始数据、回答相同问题，均不获得隐藏标准答案。提示明确规定输出结构、分组顺序、有效值定义和单位规则。评分器逐字段比较下载文件，整数严格匹配，浮点按冻结容差；不以聊天文本、产品完成标记或退出码代替正确答案。程序记录的 `completed` 表示流程终止，可能仍然没有合格成果。

本轮只要求 JSON 结果。虽然收集到部分程序文件，但没有进行独立代码重运行，也没有图表语义评分。`claimed_complete` 尚未按共同盲评规则标注，因此不报告虚假完成率。

两组的资源控制、输出额度及运行生命周期仍有差异。B1 的 Token 准入使用离线估算，不能承诺精确费用上限；通用 Shell 理论上能访问同镜像内的项目辅助代码，禁止使用的提示不等于技术隔离。数据集内的来源说明仍可读取，所以本轮也不构成无泄漏的盲测。

### Iris 失败的证据与解释

该运行的产品终态为 `failed / artifacts_missing`，实际附件列表为空；独立评分也判定缺少 `answer.json`。事件中出现“预览数据集中的指定文件”，持久化计划的意图为 `file_preview`，没有工具事件或 AnalysisJob。

核对已部署源码与本地源码哈希后，发现以下触发链：

1. [任务路由](../backend/app/domain/services/flows/plan_act.py) 的文件预览关键词包含裸子串 `open`，判断使用子串包含关系。题目中的数据集标识 `open-uci-iris` 因而命中；提示同时明确提到 `iris.csv`，定量分析被覆盖成预览意图。
2. [执行器](../backend/app/domain/services/agents/execution.py) 对 `file_preview` 使用确定性预览分支；其支持扩展名清单不含 `.csv`，存在在任何工具调用之前拒绝执行的条件。
3. 预览路径没有产生题目要求的结果文件，交付检查最终如实报告失败。

**已确认的是路由误判和预览能力不匹配。** 离线提取原分类函数，以原提示和 CSV 文件元信息复现：即使传入分析意图仍命中预览；仅将数据集标识改为不含 `open` 的 `sample-iris`，就不再命中。该核验没有调用模型或重跑任务。原始最终步骤未保存具体预览 guard 的完整文案，因此不能从存档断言 CSV 扩展名检查一定是最先触发的拒绝条件。这不是可归因于模型数值计算能力的失败。

执行 trace 没有模型请求记录，但该会话另有一条未关联 task_id 的用量记录，共 2,640 Token，与前置 bootstrap 的记录方式一致；不能把“没有执行阶段 trace”写成“没有模型调用”。本轮保留失败原样，未修改生产路由或重跑该题。

首个基线的分析与成果验收通过，但清理阶段发现 Docker SDK 客户端不支持所用的上下文管理写法。评测器立即暂停后续任务；核对容器创建时间、挂载及成果哈希后，只删除该次运行所属容器。随后修正评测器的客户端关闭与容器身份核验逻辑，再执行计划中剩余四次。原运行保留 `sandbox_removed=false`，恢复操作记录在单独文件，没有把旧记录改成成功，也没有重放模型。

前两次没有保存逐运行的评测器源码哈希；后四次补齐。产品、任务和 gold 保持原样，但评测器在批内发生过上述开发修正，因此这批必须标为开发校准，不能冒充冻结后的正式实验。

本次仅新增评测代码与文档，未修改生产功能、提交、推送或部署。模型调用使用用户明确批准的现有服务与费用范围，已在六次分析上限处停止。

## 7. 进入正式实验前的工作

1. 修复并离线验证预览误判：分析请求中出现 `open` 数据集名或文件名不能覆盖统计意图；用真正预览请求与各种分析请求同时检验，再以新的实验标识复测。
2. 实现同工具 ReAct（B2），统一各方法的逐请求资源准入、模型输出额度、计时边界和物理请求计量。单纯切换产品 Profile 不能充当独立 B2。
3. 对 36 道开发题完成系统校准，再引入独立来源族划分的盲测数据；补充代码重运行和图表语义评分。
4. 冻结评测器、提示词、任务、预算与统计方案，再执行[论文方案](comparative-experiment-design.md)中的正式比较。后续样本量应依据更多独立来源的预实验估计，不能由本批三题外推。

这些是下一阶段工作，本轮没有执行新增付费跑测。
