# 数据库文件只读可视化集成

日期：2026-09-11。选型来源见 [数据库文件清单](./database-visualization-candidates.md)。本轮是数据库**文件**的只读探查，不是数据库管理平台；不增加远程连接、账号密码、SQL 控制台、恢复备份或写回操作。

## 新增能力

| 独立 Cordis 插件 | 文件 | 实际阅读工具 | 使用方式 |
| --- | --- | --- | --- |
| `viz-duckdb-table` / DuckDB 只读数据库 | `.duckdb`、`.ddb` | 固定 DuckDB 1.5.5 | main 普通实体表结构、选列、分页 |
| `viz-dbf-table` / DBF 只读数据表 | `.dbf` | 固定 dbfread 2.0.7 | dBASE III 无 Memo 单表，字段与有效记录分页 |
| `viz-access-table` / Access 只读数据库 | `.mdb`、`.accdb` | 固定 libmdb 1.0.1 + 专用有界原生适配层 | Jet 4 / ACE 2007、2010 普通本地表，受支持标量字段分页 |

三个插件默认可用且各自独立启停，共用受信 `database-table` 前端适配器和读取器。唯一规范仍是 `contracts/visualization-adapters.json`，由它生成 Python、TypeScript、Node 三端批准映射；保持 **契约版本 2**，没有新接口或第二套协议。新增后源目录为 **77 个插件、74 个适配器**。

既有 SQLite 插件及其更严格的快照范围保持不变。DBF 新插件优先级低于原 Shapefile 插件，原地图默认选择保留；单独查看 `.dbf` 属性时可在预览方式中选择「DBF 只读数据表」。原 Parquet／Arrow、HDF5、NetCDF、办公文件和领域预览不替换。

## 用户操作

1. 在「插件 → 可视化」启用所需数据库插件。
2. 从数据集文件或已上传文件打开支持格式，在预览方式中选择相应数据库阅读方式。
3. 首次显示表目录；选择表、字段、起始偏移和页大小，点击「读取数据库分页」。不自动扫描用户数据行。
4. 可以翻页、查看字段类型／空值约束，或展开「当前页数值图表」。图表只使用已经返回的这一页，不再查询数据库，也不调用模型。

每页最多 200 行 × 16 列；修改选项先清空旧页面，手动读取后才显示新结果。文件版本、插件启停状态或预算变化会取消过期请求；关闭后释放界面。未知约束显示「未知」，不将推测的 nullable／主键当成真实约束。

## 精度与科学语义

- 整数与定点小数以精确十进制文本传输，不转换为 JavaScript 浮点数。DuckDB 支持受限标量类型中的 128 位整数、38 位 decimal，以及原样的纳秒时间文本。
- NULL、空字符串、false、0、BLOB 和非有限值分别标注。BLOB 仅显示长度，不解码或下载内容。超长／不安全文本明确显示省略原因。
- DuckDB 按快照 rowid 升序；DBF 按有效记录次序（跳过已删除记录）；Access 按本地表导出次序。后两者的行标识是当前快照阅读序号，不是业务主键或永久 ID。
- 当前页图表只接受有限 REAL 和 JavaScript 可精确表示的整数。定点小数、超大整数、NULL 和其他类型不隐式转换；显示排除数量，不填成 0。横轴是当前页次序，不猜测时间、坐标或单位。
- 没有 COUNT 全表统计、连接、聚合、自动单位推断或全库完整性检查。表格分页不代表整个数据库已经完整扫描。

## 各格式的边界

### DuckDB

上传前须关闭写入连接并 checkpoint，提供自包含单文件。只收到主文件字节时，无法判定旁边是否有遗漏的未合并 WAL，不能承诺看到所有尚未持久化的事务。加密文件、依赖外部扩展／文件的内容和不可兼容版本不支持。

仅列出 main 的实体表；不执行保存的视图、宏或查询。生成列、带默认表达式的列、嵌套／复杂类型等标为不可预览，不能用假 NULL 代替结果。用户字段遮蔽 `rowid` 时明确拒绝，而非猜测排序。

连接建立之前就关闭外部访问、自动安装／加载扩展、社区与未签名扩展、Python replacement scan、持久 secrets，锁定配置；只读连接指向私有临时副本。单线程，64 MB 引擎内存预算，15 秒中断，不将该引擎设置冒称整个进程的 RSS 硬上限。

临时磁盘溢写配额固定为 **0 字节**，也在打开数据库前配置；内存不足时明确拒绝，不降级为写磁盘。默认临时目录仅位于私有副本目录中，读取器仍检查未产生旁车文件并回收整个目录。这避免 Linux 初始化顺序与 `temp_directory=''` 的冲突，未临时放开外部访问或扩展权限。

### DBF

首版支持 dBASE III `0x03`，字符 C、数值 N、浮点 F、逻辑 L、日期 D 字段。拒绝 Memo／DBT／FPT、FoxPro 的 nullable 位图、其他未验收方言与未知编码，不遍历邻接文件。文件编码来自语言标识；未声明编码时仅按 ASCII，不猜测中文编码或用替换字符修复。

N 字段保留十进制语义，去除填充和规范化前导零但不经过浮点，保留小数末尾的零；C 字段只去除固定宽度的尾部空格，嵌入或尾部 NUL 不会被库默默裁掉，而是明确省略为不安全文本。空白 N、全空格或 `00000000` 的 D、`?`／空格 L 是缺失值，空白 C 是空字符串；不将任意非法日期或逻辑字符当作 NULL。F 先检查十进制／指数词法，再读取浮点，不接受星号包裹数字等隐式修复。

分页中跳过已删除记录。结构检查验证完整头、字段长度、128 列上限、每条记录标记、声明记录数和文件实际长度；未知编码严格拒绝，已验证语言标识 `0x7A` 的 GBK 中文。只解析用户选中的有效记录字段，不解析未选择字段的业务内容；这不是大文件分块读取。专属 **34 项测试通过**，覆盖上述语义、精确小数、空表、选列、非法头／Memo／FoxPro、清理与原件不变。

### Access

真实 oracle 覆盖原创 Access 2000 MDB 与 Access 2010 ACCDB。范围不等于全部 Jet/ACE、密码／加密数据库或复杂 Access 应用。数据只读打开，不加载窗体、VBA、保存查询、链接表或外部连接。

没有直接采用 `mdb-json`／CSV 全表导出：它们会混淆 NULL 与空字符串，并可能整体读取 OLE。也不使用会加载 `MSysObjects.LvProp` 的便利目录函数。专用适配层只读取固定目录字段 Id、Name、Type、Flags，最多检查 128 个目录条目；过滤系统、链接、查询、窗体和宏对象，不遍历其内容。

在原生行解析之前检查行范围、NULL 位图、变长字段数量和偏移目录，之后仅转换选定的标量字段。原始列名也先校验长度、Unicode 与 NUL，防止 C 字符串截断后冒充正常列名。内联 Binary 只返回实际长度；Memo、OLE、多值／附件等复杂列显示不可选，仍可选择同表其他普通列，不以假 NULL 替代或提取附件。未读取表属性时无法确认的约束显示未知。Access 日期保留本地墙上时间，不添加不存在的 UTC 时区。

本轮不支持 Jet 3、加密页、损坏或仍在写入的副本、需跟随溢出／重定位行的布局及 UCS-2 范围外字符；遇到这些边界明确拒绝，不自动修复数据。读到表尾时会与目录记录数核对，异常短读不能当作正常空表。每个原生子进程另限 12 秒 CPU、15 秒墙钟、256 MiB 地址空间；stdout 在缓冲前限 2 MiB，stderr 限 8 KiB，任何原生诊断或非零退出都失败关闭且不透传原始内容。

专属 **31 项测试通过**，其中两个实际 Jackcess 文件验证中文、NULL 与空串、`NUMERIC(28,4)`、超 JavaScript 精度数字、MONEY 最大值 `922337203685477.5807`、布尔、日期、Binary 长度、分页及空表；另验证复杂列禁选但普通列可读、链接表拒绝、畸形 NULL／变量目录、NUL 元数据、真实子进程输出预算、超时终止及私有副本回收。测试不读取业务文件。

libmdb 在独立构建阶段按官方 release SHA-256 校验编译；运行时只带库和本项目适配程序，不带 SQL/ODBC/GUI 或构建依赖。动态库放在专属目录，不覆盖 LibreOffice、GDAL 等已有系统库。保留 LGPL 文本，来源和复现路径见选型文档；非商业使用仍须遵守许可。

## 统一安全边界与效率

输入上限为完整 **16 MiB**，输出上限 **2 MiB**，目录最多 32 表 × 128 列、64 KiB 结构信息；单次偏移最多 100,000、文本单元格最多 512 UTF-8 字节。大库应走专门的分析流程，不扩大现有预览预算。

后端只验证数据契约，不加载 DuckDB 或 libmdb。原件沿用所有者、文件版本、Cordis revision、插件启停和私有产物检查，经既有有界存储读取后交给无网络、非 root、只读根文件系统的一次性 worker。没有原始数据集挂载、凭据、Docker socket 或公网端口进入读取器；临时副本不可写，正常／异常均回收。Access 原生子进程另有限制和有界 stdout/stderr。路径、数据库原始报错和 SQL 不返回浏览器。

性能改进是避免不必要的行读取、只返回所选列、有限分页、惰性图表和取消过期工作；不虚构加速百分比。whole 模式每次请求仍取回完整受限快照，偏移查询可能顺序跳过前面的行，不是常数时间的大库随机访问。
