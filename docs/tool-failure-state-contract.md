# 工具失败与只读合同

工具报错不等于任务必然失败，也不等于可以自动重试。只有已解析工具的静态 `execution_contract` 完整校验通过，且非空 `effects` 仅包含 `sandbox_read` 时，该工具失败才记为 `idempotent`：读取未完成，但不会留下不确定写入。错误仍保持 `status=error` 和 `success=false`，普通缺文件、参数错误或网络错误不会因此自动重试。安全超时重试使用已有的明确只读超时合同。

调用参数、模型消息、工具返回的 `data` 或额外元数据不能自行声明“无副作用”。写入、浏览器、网络、Shell，以及缺失或无效的合同，在失败后没有独立可信执行凭据时继续保守标记为 `unknown`。一次真正未知的执行结果不会被后续成功或只读失败清除；任务能否完成仍由实际成果验收决定。

核心 `file_read`、`file_find_in_content`、`file_find_by_name` 具有显式只读合同。前两项的 `sudo` 只接受 `false`（默认值），不再支持提权读取；`true`、`null` 和类型不符的值在调用沙箱前拒绝，避免旧沙箱的提权命令分支与只读保证矛盾。普通文件读取和查找保持可用，写入工具的权限或合同不因本次变更而放宽。

## 执行凭据与终态核验

真实 Shell 适配器在启动前生成私有操作身份，按工具调用及执行代次记录。沙箱返回由服务观察的版本、操作身份、命令摘要、服务实例身份、退出码和原进程组静止证据。普通模型或插件结果不参与凭据判定；凭据不会进入模型消息或浏览器。后续等待、查看和取消使用原操作身份校验，不能误读或误取消复用相同 Shell 名称的新执行。

`confirmed_terminal` 仅表示原进程已退出且原进程组静止，不等于执行成功，更不等于可以重放。非零退出保持工具失败；零退出但输出获取失败单独记录 `shell_output_unavailable`。只有明确未启动的操作才因该凭据获得 `replay_safe`。是否完成仍要求真实成果验收，跨任务续作也不能据终态自动重复任意 Shell 写入。

已成功执行、但没有重放保证的非只读操作单独记录为不可重放，包括没有 Shell 凭据的外部/MCP 操作。它们不因此变成“执行未知”或阻止当前任务正常完成，但会阻止把失败步骤当作可重放计算跨任务续作。后续只读成功或另一操作的“未启动”凭据不能清除这一记录；摘要只输出计数，不输出操作身份。

收尾核验只查询原操作，不启动或取消命令：默认最多查询 4 个操作、总计 3 秒，每个操作最多 2 次，其中至少 1 次留给最终收尾；调用方不能突破 8 个操作、5 秒的硬上限。刚收到“仍在运行”的凭据时避免立即消耗早期核验。已审计的核心等待/查看工具可继续观察已有操作，但必须使用原操作身份；等待超时仍只允许取消该原操作，不获得新写入权限。主动等待工具受原工具预算约束，不占用这两次被动核验额度。沙箱查询也有进程扫描数量及时间上限。重启后缺失的记录、未知代次、查询失败或只有主进程退出而仍存在活动子进程，均保留未确认。沙箱记录达到容量后拒绝新操作，不删除旧身份来允许重复执行。

## Mongo 隔离验证

`backend/scripts/check_checkpoint_mongo.py` 需要显式设置 `DATASEEK_REGRESSION_MONGO_URI`。脚本只在内部随机命名、确认原先不存在的临时数据库中验证续作状态的原子性，完成后核对归属标记并删除该库；不使用应用数据库名，不启动模型或沙箱。输出仅包含通过数量、失败标志和临时数据库清理结果。
