# 实验运行记录 v1

本版在对话式 Data Skills 实验室中增加独立的运行身份和可查询历史，不改变任务执行权限，也不自动重跑分析。它是 LAB-02/06 的基础交付；数据检索、下载登记和恢复 worker 仍是后续任务。

## 持久化与身份

沙箱 Agent 开始处理一条已有持久化序号的用户输入时，先登记 `RunEvent(phase=started)`，再进入分析。`run_id` 由会话 ID 与触发输入序号确定性生成，不使用前端随机状态或模型文案。记录中的 `source_event_seq` 指向原问题；`started_at` 沿用该输入的时间，表示这次运行的逻辑起点，不用于计算模型或工具耗时。轻量直答和升级前的记录不补造 Run。

后续步骤、计划、工具、错误、等待和响应结束事件携带该 Run ID。步骤的公共 ID 在 Run 内派生，同一会话复用原步骤编号不会修改另一运行。`revision` 是最后纳入投影的证据序号；`plan_revision` 是最后一份计划的事件序号。这里没有新增 Attempt 身份，重试与恢复的独立 Attempt 模型尚待实现。

运行以现有 MongoDB 事件日志作为事实来源，通过索引读取并重建，不额外维护一份可能与日志不一致的完成状态。新建读取器或刷新页面仍能重建已有记录；这不等于后端重启后自动恢复执行。会话删除仍删除所属日志及运行历史。

工具与技能准备完成后登记 `phase=environment`：保留环境指纹、工具目录修订摘要、实际启用的版本化技能包 ID、SemVer 与 SHA-256；旧技能只记录数量。读取时保留首份环境凭据，后来的凭据不能覆盖它。没有凭据时明确显示尚未登记，不把用户的请求选择冒充实际启用结果。

## 状态与证据

- 单个 Step 成功不会结束 Run。
- 只有明确的计划完成事件、计划状态成功、全部步骤及其成果检查成功、没有仍活动的已记录分析作业时，才投影为运行成功。
- 部分步骤失败可投影为部分完成或失败；缺少计划/步骤终态、读取被截断、仅收到 DoneEvent 时显示待确认。
- WaitEvent 表示等待输入。继续输入形成新的运行；本版尚无跨运行恢复链。
- 已有终态不被迟到的计划或步骤事件逆转。活动作业使用其单调 revision，旧的作业快照不会覆盖新快照。
- 当前会话已不运行，或者有更新的 Run 时，缺失终态的旧运行显示待确认，不宣称仍在执行。

`recovery=inspect_only`：允许检查记录，不代表已具备安全重试能力。取消原因、后台获取队列、租约恢复和独立 Attempt 记录需要后续实现；目前仅有响应结束而没有确切失败/完成证据时不会猜测原因。

## 查询与界面

`GET /api/v1/sessions/{session_id}/runs?before_seq=...` 复用会话访问权限，不作为公开分享接口。每页最多 10 个运行，用 `next_before_seq` 继续分页。每个运行最多投影 2,000 条相关证据，超过上限会设置 `history_complete=false` 并降为待确认，而不是把前缀当作完整历史。

公共响应仅包含运行/步骤身份、状态、时间、版本引用和指纹。数据库查询剔除工具参数/输出、步骤输入/输出/正文及计划正文；响应也不提供宿主路径、命令、环境变量、密钥或自动重跑入口。

聊天页的“实验运行”面板按需加载，展示阶段和技能版本；展开时随新事件限频刷新，支持加载更早运行与手动重试。切换会话或关闭面板会中止请求，过期响应不能污染当前页面。旧会话显示无运行记录。

## 验证与当前边界

回归覆盖真实 Runner 的逐输入登记、同会话隔离、迟到事件、阶段/任务终态分离、活动作业阻止成功、环境凭据不可覆盖、录制回放、权限与分页，以及前端请求竞态和失败反馈。

本版没有新增 Experiment 容器、数据来源/输入版本/Artifact 关联、计划编辑与依赖调度，也没有完成 LAB-02/06 全部验收。下一步按升级计划推进 LAB-03 数据候选与版本记录，再接 LAB-04/05 的 NCBI 检索和获取，最终让技能驱动实际数据闭环。
