# 统一 Chat 与数据集探查

## 范围

保留 `/chat/:sessionId` 和 `/dataset/seek/:datasetId` 两个入口，统一分析会话控制、成果展示与输入处理。不迁移或重跑旧任务，不增加任务消耗额度，不改变本机 `127.0.0.1:7001` 部署边界。

## 前端

- `useAnalysisSession` 是发送、停止、续作、事件归并、断线恢复、历史分页和销毁的唯一控制层。页面通过 hooks 处理导航、标题、数据集历史等外壳行为。
- `AnalysisConversation` 共用消息列表、过程折叠、成果图库、追问，以及 Shapefile / 分子预览入口。输入附件不进入成果图库，专用成果预览只选当前轮已交付文件。
- Chat 的“本次分析资料”展示服务器认定的用户输入，不把任务全部文件或模型声称的路径当输入清单。勾选仅决定下一次请求；运行中锁定范围，取消勾选不删除文件。
- Home / Chat 支持仅上传文件提交，界面明确说明并发送“概览内容、结构与可分析方向”的问题。上传未完成时不能提交。
- 资料查询和会话请求均隔离过期响应；路由切换继续使用现有预览生命周期清理。

## 输入契约

后端 `AnalysisInputContext` 描述数据集和用户上传两种来源。每份资料具有稳定身份、来源组、逻辑路径和服务端运行位置。它不是数据集登记，也不是可由浏览器自行构造的授权清单。

上传原件保留在现有文件存储中；本轮文件物化到沙箱 `/home/ubuntu/inputs/<server-group>/<filename>`。同批上传的关联文件保持同组；重名文件按身份消歧。数据集仍通过原有 allowlist 校验和只读挂载。

`GET /api/v1/sessions/{id}/analysis-inputs` 返回可用输入文件和当前选择。

`POST /api/v1/sessions/{id}/chat` 的 `input_file_ids`：

- 省略：继承上一轮已接受输入的选择。
- `[]`：明确清空上传资料选择，不清除绑定的数据集。
- 指定 ID：只选择本会话中由用户明确提交过的文件。
- 当前 `attachments`：在上述选择中追加本次新提交文件。

每轮受理时固定输入快照并重新检查文件访问权限。后续输入不能改变已受理任务，自动生成成果不会悄悄加入分析资料。生成成果的下载与预览仍可直接使用；再次作为输入需要用户明确提交。

## 执行与恢复

数据集和上传文件通过来源适配接入同一目录查询、目标解析和常规分析快路径。Skill、MCP 和图像理解仍按能力走专门编排，不用 URL 或页面名决定执行能力。

上传续作必须绑定原始输入 ID、运行位置、文件大小、完整输入清单和内容指纹。沙箱指纹接口默认拒绝输入根，仅接受后端提供的精确名单；保持 no-follow 路径校验和内容变化检测。无法确认副作用或来源时，不自动重放原计算。指纹快照大小边界只控制能否安全续作，不是分析额度限制。

## 连续追问的契约与交付

- 本轮前置决策的输出要求随消息传入执行层。明确不要求文件且没有交付清单时，后续路由和完成核验不能再自行添加图表义务；否定动作不作为正向关键词。
- 已发布成果保留独立存储对象。下一轮覆盖沙箱中的同名工作文件，不得删除前轮已经交付的版本。失效或失去访问权限的附件不能令整段历史读取失败，也不能通过旧链接绕过授权。
- 审阅与只读纠错共用证据规则，但每次调用只使用自己的响应结构。明确区分输入文件介绍与成果交付；引用失配可经过现有的一次逐段纠错，之后仍执行完整的证据、路径与状态校验。纠错不能通过修改段落类型来绕过证据要求。未通过的内容保持未发布，不自动重跑分析。
- 审核诊断仅保存固定错误码与计数，不写入引用原文、文件内容、来源 ID 或路径。
- 连续追问可以解释同一输入范围内上一轮已核验的事实，但必须标明历史归属，不能声称本轮重新读取、计算或交付。简单事实问答不强制附加方法或限制段；新执行、执行失败和当前交付仍需相应的实际证据。

## 验收要点

1. 同一数据以数据集 / 上传方式进入，使用共同会话控制与成果界面。
2. 首问、无再次上传的追问、追加文件、明确清空及同名文件选择。
3. 分页、刷新、断线重连、停止、切换会话、迟到响应和重复事件。
4. 图表 / 数据表交付、预览、下载，以及输入附件和生成成果隔离。
5. 越权文件、伪造身份、路径穿越、软链接、源内容变化和续作范围变化拒绝。
6. 前端类型检查/构建/测试，后端与沙箱回归，Compose 配置校验。
