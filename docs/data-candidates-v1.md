# 数据线索与版本登记 v1

这是 LAB-03 的第一批交付：会话内记录人工提供的数据来源，并将已有文件登记成不可覆盖的内容凭据。它不代表互联网检索、下载队列或不可变原始文件保管已交付。

## 使用方式

聊天页展开“数据线索与版本”，填写名称、公开 HTTPS 来源和外部标识（accession、DOI 或数据集编号）。查询参数与片段会被移除，所以数据身份必须单独填写。禁止填写凭据和本地路径。

保存后点击“查看版本 / 登记文件”，选择当前已加载会话中的附件。后端重新读取当前用户拥有的文件，分块计算 SHA-256。每个文件上限 64 MiB，一次最多 16 个、合计 128 MiB。旧消息未加载时，其文件可能不在选项中，加载对应历史消息即可。相同来源观察和相同文件集合的重复请求返回原记录，重试不会生成重复版本。

界面始终注明“用户提供来源 / 未核验”和“已登记摘要 / 来源关联未核验”。登记不会下载远程数据，不会改变现有目录或只读挂载，也不会自动触发分析或声明分析成功。

## 模型与持久化

- DataCandidate：不可变的来源观察，包括来源 URL、外部标识、名称和记录时间；不同名称产生新观察，同一用户、来源 URL、外部标识对应同一 asset_id。
- DataVersion：关联 candidate_id、asset_id 和有序文件清单。文件清单仅含文件 ID、字节数、内容摘要，不包含真实存储路径或私有元数据。
- AcquisitionReceipt：本批固定 method=uploaded_files、source_verified=false；只记录用户将文件关联到来源的动作，不能由客户端声明已验证。
- retention=reference_only：这里只保留不可变登记记录，不复制或冻结原文件。原文件删除或不可用后，记录仍可读；不得将它当作可恢复的数据备份。

独立 MongoDB data_provenance 集合采用基于所有者、会话、记录类型的哈希分区和内置 _id 索引。有界分页每次 20 条，按稳定 ID 顺序，不保证时间倒序。创建只使用 insert，唯一键冲突返回已持久化内容；版本和获取凭据在同一个文档内原子保存。身份包含当前文件 ID，所以重新上传相同内容到新文件 ID 会产生新的登记版本。

四个接口位于 `/api/v1/sessions/{session_id}/data-candidates`：GET/POST 线索，GET/POST `/{candidate_id}/versions`。全部经过会话所有权校验；仓储再次以当前用户和会话隔离。文件读取每次携带当前用户 ID，前置大小/所有权校验和有界读失败时不写版本。读取接口不返回私有 FileInfo。原文件在存储层按独立对象写入，本接口没有覆盖文件操作。

来源链接仅作引用，本批从不访问它。公开链接校验不构成未来下载器的 SSRF 防护：连接器实现时仍必须对 DNS、重定向和每次连接目标重新校验，并记录实际来源与供应方版本。

## 后续

NCBI 连接器将补充官方检索结果、获取任务、供应方修订号与实际下载凭据；原始文件保管、运行输入绑定和保留策略需单独交付。当前不可将人工来源转换成 connector_verified，也不可从历史对话补造来源证明。
