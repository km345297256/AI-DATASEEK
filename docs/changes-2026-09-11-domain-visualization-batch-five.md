## 新增能力与边界

| 插件 | 首版支持 | 交互与限制 |
| --- | --- | --- |
| `viz-sqlite-table` | UTF-8 SQLite 3 普通 rowid 表，`.sqlite/.sqlite3/.db` | 先查目录，再明确选表、列、分页；全文件最多 16 MiB，每页最多 200 行、16 列。按 rowid 升序，无用户 SQL、连接或全表计数。整数/rowid 保留精确十进制文本；BLOB 仅长度，长文本或不安全文本明确省略。 |
| `viz-radar-window` | ODIM_H5 2.4 极坐标 PVOL/SCAN，`.h5/.hdf5` | 选择扫描、物理量、射线及距离门窗口；最多 128×128。显示射线索引 × 斜距门中心热图，不是地理投影 PPI。原始存储码为默认，用户可显式本地应用 gain/offset；缺测与未探测分别标记。 |
| `viz-ugrid-window` | HDF5 型 NetCDF4、UGRID-1.0 二维网格，`.nc/.nc4/.netcdf/.h5/.hdf5/.hdf` | 选择网格、节点/面变量、非空间维度索引；最多 4096 节点、2048 面、每面 8 节点。完整读取已限定的拓扑，再读取明确变量切片；不是无限大网格的流式浏览。原生二维坐标、节点着色或面常值，不投影、不插值。 |

三者默认启用但优先级为 40，不改已有视图的 ID、默认优先级及用户开关。用户可在“插件 → 可视化”独立启停；同一 HDF5/NetCDF4 文件可同时保留结构树、数值曲线和这些专项视图。后缀匹配只表示可选择插件，内容还必须满足读取器的格式约束。

## 协议适配

- 清单使用现有 v2 `preview` 能力，`shared=false`、`file:read`；不新增公开 SQL、文件路径或资源路由。
- SQLite 使用 `whole` 输入和严格 typed-cell 表格结果；不复用浮点数字表达 64 位整数。
- 雷达使用 `window`、`tree/image`；海洋网格使用 `window`、`tree/geometry`。`geometry` 仅对批准读取器开放，新增 `ugrid` 专属拓扑字段；旧读取器不会因请求参数获得几何权限。
- 初始目录不隐式绘图或调用模型，后续表格/图像/几何请求必须携带客户端已检查的文件版本。选项、目录、选择、格式、文件大小及实际范围读取量均经后端再次校验。
- 共用现有取消、卸载、版本改变、插件撤权及输出预算机制；保留 AgentLoop、PlanActFlow、FastAPI、SSE、AnalysisJob 和 Artifact Store。

## 读取、安全与科学语义

雷达与 UGRID 源文件最多 8 GiB；每次累计取回最多 8 MiB、128 次，每个范围最多 1 MiB，最终统一响应最多 2 MiB。HDF5 固定大小属性、链接、类型、压缩块和解码预算独立检查；不加载外部链接、VDS 或用户过滤器。窗口预算不表示支持任意布局、压缩和维度组合。

SQLite 仅在既有一次性沙箱增加 `apsw==3.53.4.0`，使用公开 SQLite 安全控制：只读 immutable 连接、禁用扩展/触发器/视图/虚拟模块、关闭不可信 schema、固定 authorizer、语句/单值/堆内存/执行步数和时间上限。拒绝 WAL 主文件、视图、虚拟表、生成列、WITHOUT ROWID、加密及不支持的 schema，不读取旁路日志文件。临时副本只在该无网络、非 root、无源数据挂载、只读根文件系统的 worker 私有临时目录内，结束即清理。

ODIM 2.4 的 `rstart` 按米解释，门中心为 `rstart + (gate + 0.5) × rscale`。不把旧版千米语义套入 2.4；不以 `a1gate` 猜测每条射线的地理方位。缺测/未探测先分类，不能把未探测当零再标定。

UGRID 按明确的维度关联、`start_index` 和尾部填充值恢复拓扑，区分 node 与 face。坐标不得缺失或非有限，拒绝非恒等坐标打包及跨日期变更线的简单连接；变量的缺测/非有限值标记为空，不自动应用 CF scale/offset、时间、垂向或坐标系推断。打包字段仍标作存储值，声明单位不意味着已完成标定。
