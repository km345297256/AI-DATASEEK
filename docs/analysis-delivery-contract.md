# 分析成果交付与同任务续作

## 完成标准

流程结束不等于分析完成。前置决策提取用户要求的成果类型、数量、格式；多步骤计划把任务级最低要求保留到最后一步，不能因重新规划而减少。每个产出步骤也可声明自己的清单。规划器不能自行把新步骤标记为已完成。

成果分为 `image / table / report / code / any`。开放的可视化请求至少要求一张图，不强制固定四种图。代码只满足代码交付要求，不能抵扣图片、表格或通用成果。每个实际文件最多抵扣一个清单计数。

执行器返回的 `success` 只是执行声明。后端还会验证文件内容，并核对实际上传的 SHA256 和大小。必需成果缺失、损坏或未交付，以及执行状态未知，都不能标为完成。辅助文件不自动成为必需成果；必需成果全部满足后，额外文件的问题只形成非阻断提示。

公共消息的 `metadata.analysis_outcome` 提供 `succeeded / partial / failed`、受控原因、缺少项、逐文件 `issues` 和可选续作入口。`issues` 仅包含安全文件名、类型、受控原因及是否阻断，不含私有路径或原始检查回包。模型分析说明保留，与权威完成状态分开显示；失败说明明确标注完成状态以成果检查为准。模型总结不能覆盖该状态或追加未经验证的附件。

`DoneEvent`、任务 `COMPLETED` 表示这一轮不再运行；步骤/计划的执行状态与 `analysis_outcome` 才表示是否完成用户要求。未执行的剩余步骤不会自动变成成功。

## 工具调用与预算

真实工具 schema 在所有治理、作业和执行前统一校验，覆盖内置、插件、MCP和 Code Mode 内部调用。必需参数、类型、嵌套约束、未知字段均检查；错误反馈只包含字段位置和类型，不回显参数值或凭据。参数错误直接交回执行器修改，不进行相同请求的机械重试。

未知执行状态不自动重放。只有适配器明确保证“尚未执行”或“同一请求幂等”的瞬时失败，才允许有界重试。错误同时标记消息和工具结果为失败。

只有完整静态合同明确声明纯沙箱读取的工具，其失败才按无写入副作用处理；普通只读错误仍不自动重试，但恢复后不会污染最终完成状态。工具结果自行声称“安全”无效。核心读取/文本查找不再接受 `sudo=true`，以保证这一声明在历史沙箱上也真实成立；Shell、浏览器和网络操作不凭名称推断安全。

生产任务不设累计工具轮次、模型调用、Token 或总时长额度，也没有“审核增加额度”机制。保留调用计量、单次操作超时、资源安全边界、用户取消和无进展检测；这些保护不以消耗量决定用户任务是否值得完成。

## 通用成果修复

同一次请求中，必需成果检查失败会反馈给执行器。修复请求包含原目标、未满足的类型/格式/数量、失败文件的内容指纹、结构化诊断及已验证成果清单。它不包含按数据集名称、文件名或固定维度选择的修复配方。执行器必须检查真实结构，不能靠丢弃数据、猜维度或放松验收标准通过检查。

- 只在前一轮操作有可信终态证据、没有待确认副作用时安排新的局部操作；不重放原任务。
- 当前执行生成器完全结束后才进入修复；取消与输入身份检查仍在新操作前生效。
- 每次修复重新核验内容与上传字节；只有必需缺项减少或结构化检查证明错误改善，才继续修复。换名、改空白或仅改变指纹不代表进展；重复状态或循环停止，不按累计消耗停止。
- 已上传的有效成果保留。若修复改写了已验证的工作副本，停止修复并保留原上传对象，不把新副本冒充原成果。这不是对任意 Shell 写入的文件系统级预防保证。
- 可选文件问题不触发修复，也不阻断其他必需成果修复；未支持格式、权限/路径问题及检查服务不可用，不通过反复调用模型解决。
- 已验证内容的上传失败由宿主尝试重新交付，不调用模型重新生成；存储仍不可用时不启动混合内容修复。
- 中间检查与修复只显示单条瞬时进度，最终说明和验收状态只在完成或无法继续时交付。

生产逐文件诊断写入服务端 `analysis_delivery_checks`，按所有者、会话、输入序号、步骤与检查批次关联。原始文件内容与工具回包不落入该诊断记录；公开事件不包含该私有记录。审计写入失败会阻止新的自动修复，但不会否定已经验证且交付的成果。

## 同任务续作

部分完成时，只有能够证明来源和进度未变化，才保存24小时私有检查点并提供“继续未完成部分”。用户点击后发送同一会话内的新请求身份和不透明检查点标识，不需重述目标。

- 原目标、数据选择、已完成步骤、技能、MCP权限和有效模型配置从服务器记录恢复；不接受客户端更改。
- 源数据、验证通过的阶段成果有完整内容指纹；领取前后及执行前验证身份、期限、输入序列和指纹。
- 同请求身份重复提交、断线重连不会重复执行；不同身份不能重复消费同一个检查点。
- 新的普通输入使旧检查点失效。写前输入栅栏和写后持久化标记避免跨进程竞态。
- 成功步骤跳过；未完成步骤复用已验证的阶段成果继续，仍受原安全审核、工具权限与取消控制。对于尚未完成步骤中的复杂操作，这不是任意程序指令级断点恢复。
- 仅上传失败且所有计算步骤已经成功时，只补验证和上传，不调用分析模型重做计算。
- 出现不确定副作用、数据/配置变化、快照不全时不提供安全续作。不会自动重跑用户任务。

当前检查点限定于有完整指纹的数据集分析，不支持带新上传附件的任务。快照最多64个来源/成果路径、128 MiB读取量；检查点最大256 KiB。超过限额会保留明确的未完成状态，不伪造可续作证明。

## 验证范围与部署

目前支持完整解码的常见位图、CSV/TSV、XLSX、结构化JSON、非空TXT/Markdown/HTML，以及只解析不执行的代码分类。每批最多32文件、每文件32 MiB、每批128 MiB，图片最多1600万像素，另有帧数/表格/压缩展开限制。PDF、DOCX、SVG及未支持的科学数据格式不计为已通过内容验收。格式或结构验证不等于证明统计方法、图表表达或分析结论正确。

按现有 `./run.sh` Compose 更新前后端及沙箱镜像；本机入口保持 `127.0.0.1:7001`。先确认没有运行中的任务/输入。此次不迁移旧环境、不修复或重跑旧任务；新建数据集分析会话使用新镜像。

回归测试覆盖参数合同、错误重试、预算阶段、损坏/缺失/错类型/重复计数、上传字节变化、公开投影与权威状态一致性、来源变化、跨身份/过期/重复领取、输入写入竞态及断线恢复。日志仅记录受控状态、原因和数量，不记录私有检查点或真实主机路径。
