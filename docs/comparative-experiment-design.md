# DataSeek 论文对比实验方案

设计版本：2026-09-14；实施状态更新：2026-09-15。适用目标：论文、课题验证与可复现实验。

本方案依据仓库 `v2` 的 `9b95762b601455939e21e1077c35d0aa980dc0a6` 设计。这里给出的是正式实验协议，样本规模、预算和目标差异均为设计建议。现已新增独立评测器、36 道开发题，并完成获批的首批 6 次 B1/D 校准；实测结果和限制单列于[首批预实验报告](experiment-pilot-2026-09-15.md)，不代替下文的正式实验。

## 1. 论文要验证什么

建议围绕一个核心问题展开：**在相同基础模型和资源条件下，DataSeek 能否更可靠、更经济地将异构科学数据转化为正确、可追溯、可复现的分析成果？**

将贡献限定在数据集探查与分析链路，重点验证以下问题：

| 研究问题 | 对应机制 | 需要的证据 |
| --- | --- | --- |
| RQ1：能否提高分析完成质量？ | 数据结构探查、科学分析工具、执行反馈与成果交付 | 独立评判的任务成功率、科学正确性、成果完整性 |
| RQ2：工具多时能否降低调用成本？ | 领域 Preset、按需加载工具 | 相同或可接受的成功率下，总 Token、模型调用数及延迟下降 |
| RQ3：大数据与长链路下能否保留关键证据？ | 窗口读取、Spill 分页、成对上下文压缩 | 关键证据检出率、超上下文失败率、读取量、峰值内存 |
| RQ4：故障发生时能否正确恢复并如实报告？ | 成果验收、局部修复、上传恢复与有条件续作 | 恢复成功率、虚假完成率、重复执行数及额外开销 |

推荐问题质量、交互式可视化、Code Mode 和领域 SubAgent 作为扩展实验。它们不必全部进入主论文，否则很难解释具体收益来自哪里。

## 3. 对比方法：同时回答“系统有用吗”和“机制有用吗”

### 3.1 主实验的五组方法

| 编号 | 方法 | 能力与限制 | 比较目的 |
| --- | --- | --- | --- |
| B0 | 单次代码生成 + 执行 | 同一模型读取统一初始目录信息，生成一次分析程序；允许执行，但不把报错反馈给模型修复 | 测量迭代执行整体带来的收益；只作下界 |
| B1 | 通用 ReAct + Python/Shell | 可读原始数据、执行代码、查看输出并迭代；提供相同科学 Python 库 | 与正常通用分析 Agent 比较 |
| B2 | ReAct + 同一 DataSeek 科学工具集合 | 复用相同工具实现、参数文档、初始工具及发现/加载接口、沙箱；使用通用执行循环 | 尽量分离工具能力和 DataSeek 编排机制 |
| B3 | DA-Agent | 使用作者实现；仅适配模型入口、任务输入和产物出口，记录全部改动 | 与公开数据分析方法比较 |
| D | DataSeek 默认完整分析链路 | 显式固定 `general/on_demand`，关闭两个试点；保留探查、执行反馈、Spill 和交付机制 | 被测系统 |

DA-Code 是任务基准，DA-Agent 才是方法，二者不能混写成同一个“对比模型”。其论文覆盖可执行的数据整理与分析，作者仓库提供运行和评分入口。[DA-Code 论文](https://aclanthology.org/2024.emnlp-main.748/)、[DA-Agent/DA-Code 作者代码](https://github.com/yiyihum/da-code)。

B2 必须让 Agent 真正获得与 DataSeek 相同的工具文档和调用机会。工具包装内部仍保留路径校验、只读数据挂载等公共保护；额外延迟、Token 与实现差异均记录。若复用包装会顺带引入某项 DataSeek 机制，应如实列为共享机制，不能再宣称已经完全隔离它。

所有方法使用共同的成果收集适配器，保存实际生成的最终程序/有序代码单元、执行日志和输出文件。B0 的生成源码也自动作为代码成果收集；不因某框架没有附件按钮而让它机械性失败。适配器不能补算法、修复代码、替模型编写说明或制造缺失图表。B2 保留与 D 相同的发现接口，避免大目录无法装入上下文的平坦基线过弱；平坦工具暴露单独放在 E2 检验。

将 **D 对 B2 的差异**指定为主比较，D 对 B1、B3 为次比较，B0 为下界。B2 的差异仍涉及多种机制，因果归属依赖后面的消融，而不是只靠一张总表。

### 3.2 可选补充方法

- **TaskWeaver**：适合作为有状态代码执行、规划及插件框架的历史对照。官方仓库已于 2026-03-23 归档；冻结可复现版本，不当作当前持续维护的最新系统。[官方仓库](https://github.com/microsoft/TaskWeaver)
- **DS-Agent**：放在监督学习子集，评价训练流程及分类/回归结果。作者实现的案例库聚焦表格、文本、时间序列；扩展到 FITS、NetCDF、分子结构等会引入额外案例工程，不适合未经适配就覆盖主实验九领域。[官方实现](https://github.com/guosyjlu/DS-Agent)

不以基础模型名称充当系统基线。应在每个基础模型内部比较各方法，再讨论更换模型后差异是否仍存在。不同产品界面的人工演示只能作补充案例，不能与可控实验混成主榜单。

## 4. 数据与任务设计

### 4.1 现有资产与缺口

本轮只读清点了仓库中的 **18 份内置数据 manifest、32 份外部数据 manifest**。这证明清单存在，未重新校验外部实体、许可状态或下载可用性。

| 系统领域 | 内置清单 | 外部清单 | 主要任务素材 |
| --- | ---: | ---: | --- |
| 通用分析 | 2 | 0 | CSV、基础统计与分组分析 |
| 表格与工作簿 | 2 | 2 | CSV、XLS/XLSX、多工作表 |
| 地学与遥感 | 2 | 13 | NetCDF、SHP、栅格、时间序列 |
| 图像科学 | 2 | 0 | TIFF、PNG、已有标注掩膜 |
| 化学与结构 | 2 | 3 | PDB/MOL、实验工作簿与说明 |
| 生物序列 | 2 | 10 | FASTA、压缩序列 |
| 空间与天文 | 2 | 2 | FITS、NPY、光谱与动态谱 |
| 文档证据 | 2 | 0 | PDF 中有出处的事实提取 |
| 谱学与衍射 | 2 | 2 | XRDML、数值谱 |
| 合计 | 18 | 32 | 50 份清单，不等于 50 个均衡、独立盲测样本 |

来源清单位于 [内置数据](../backend/app/resources/datasets) 与 [外部数据](../backend/app/resources/external-datasets)。外部数据分类沿用仓库标签；任务还要增加实际文件类型、科学操作与难度标签，避免把所有 XLSX 都视为同一个任务领域。

既有 tests/fixtures 用于格式边界与故障实验。相同生成器的不同文件、压缩/解压副本、一个研究的不同工作表，均不能被计成新增独立科学数据集。

### 4.2 建议规模与划分

正式版本目标为 **54 个独立数据来源单元、216 个任务**：

| 集合 | 数据来源数 | 每来源任务数 | 任务数 | 用途 |
| --- | ---: | ---: | ---: | --- |
| 开发集 | 9，原则上每领域 1 个 | 4 | 36 | 编写适配器、提示词与评分器 |
| 验证集 | 9，原则上每领域 1 个 | 4 | 36 | 选择配置、预算、容差并冻结 |
| 盲测集 | 36，每领域 4 个 | 4 | 144 | 主论文报告 |

18 个内置样例适合作为开发/验证候选，因为项目已围绕它们做过功能开发。36 个盲测来源需要从未用于调参的外部清单及新增独立来源中遴选；当前 32 份外部清单严重偏向地学与序列，仍需补齐图像、文档等领域。现有来源若已经用于分析调试、修复配方或提示词开发，也不能直接称为未见盲测。

按 **source_family_id** 划分：同一研究、原始实验、版本衍生、配套文件和合成变体必须进入同一集合。单纯来自同一机构不必判为同一来源族；共享底层观测或研究数据才是关键。跨域来源族整体划分，必要时调整配额并公开最终数量。

54/216 是建议设计规模，不是统计功效保证。正式采样前依据预实验方差、来源内相关性与目标效应决定是否需要更多来源；增加独立来源优先于重复改写同一道题。

### 4.3 每个来源的四类任务

| 类型 | 任务要求 | 主要评分 |
| --- | --- | --- |
| T1 结构探查 | 找到文件与配套关系，识别变量、维度、单位、坐标系或文档结构 | 结构事实准确率、必需信息召回 |
| T2 数据质量 | 检查缺失、异常编码、无效几何、序列歧义、范围/单位冲突；信息不足时明确指出 | 问题识别 Precision/Recall、证据定位 |
| T3 定量或证据分析 | 完成规定统计、区域汇总、峰值、序列统计，或带页码的文档证据提取 | 数值/集合/证据与独立答案的一致性 |
| T4 成果交付 | 用实际输入生成规定的图表或证据报告，并交付计算表、说明和可复现代码 | 语义正确、成果齐全、复运行成功 |

每类题目由领域专家检查可回答性。不能要求纯论文文本提供不存在的实验数值，也不能在没有细胞标注的数据上以“真实细胞数”评分。文档任务可以交付证据表和 Markdown 报告，不强制生成没有意义的统计图。

每领域的 16 个盲测任务建议包含 4 个低难度、8 个中等、4 个高难度；以所需文件关联、操作步数和语义歧义预先定义难度，不按某个方法事后是否成功分级。四类任务分别启动干净会话；需要连续探查的题目，应把整个多步过程定义为同一个任务。

### 4.4 可直接据现有样例编写的题目

| 素材 | 题目示例 | 隐藏验收重点 |
| --- | --- | --- |
| NOAA 月气候态 NetCDF | 对题目指定经纬度区间计算逐月有效格点加权平均，交付 CSV、折线图和方法说明 | 12 个月是气候态；明确权重、缺测与经度约定；不能推断逐年变暖趋势 |
| ChemDC 电光补偿工作簿 | 按原说明区分材料和光照条件，统一指定单位并比较 I–V 曲线 | `--` 不等于零；重复列按条件关联；误差条含义未知时不自行猜测 |
| FASTA | 统计序列数、有效 A/C/G/T 碱基数、歧义比例及 GC 含量并输出表 | 题目明确 GC 分母；压缩与解压副本不重复计数 |
| SHP 配套文件 | 识别坐标系与无效几何，按指定投影计算面积汇总 | 不能用经纬度平方替代面积；任何修复仅写派生副本 |
| XRDML | 在指定横轴区间和预先规定的峰定义下提取峰位并画谱 | 尊重原始轴、计数含义和来源占位元数据，不把占位参数当真实仪器条件 |
| 文档 | 比较两个段落对可复现性措施的要求，输出可核对的证据表 | 页码/段落定位、忠实转述，缺乏依据的推断不能算事实 |

这些是题目模板，不含标准答案。标准答案应在审阅实际数据后，用独立参考程序和人工核验产生。

### 4.5 公开基准：补充外部有效性

优先增加 **ScienceAgentBench verified**：作者公布的基准含 102 个任务，2026-04-30 更新提供 verified split 与 `benchmark_verified.zip`。它以独立 Python 程序为输出，较贴近科学数据分析。建议在适配可行时运行整个 verified split，实际任务数以冻结清单为准。[作者仓库与更新说明](https://github.com/OSU-NLP-Group/ScienceAgentBench)

核查时官方 `run_infer.py` 仍使用 `split="validation"`，因此需要显式切换到 `verified` 并使用匹配数据包，保存数据 revision、哈希及适配补丁，不能只按旧命令运行后宣称使用了新版。[官方加载代码](https://raw.githubusercontent.com/OSU-NLP-Group/ScienceAgentBench/main/run_infer.py)、[官方数据页](https://huggingface.co/datasets/osunlp/ScienceAgentBench)

必须保留官方任务输入、专家知识是否可见的条件和评分协议。其任务输入已经包含一定数据说明，不能据此单独证明 DataSeek 从裸目录自动探查的贡献；该贡献由自建原始目录任务和消融验证。若因资源仅选择子集，选择规则在运行前冻结并明确标成子集。

官方汇总脚本存在从多次轨迹选最佳的协议。本方案主指标使用每次独立运行的平均成功率；如另报官方最佳轨迹指标，单独列名，不与本方案的单次运行成功率混用。官方图像评分涉及模型裁判，应保留官方分数，并另外报告人工抽查的一致性。[官方运行与评分说明](https://github.com/OSU-NLP-Group/ScienceAgentBench)

多次最佳成绩的成本必须计入全部候选运行，不能只报被选中轨迹的成本。模型输入严格按官方输入字段构造，不传入 gold 程序名、评分脚本名或金标准来源代码路径。[官方指标代码](https://raw.githubusercontent.com/OSU-NLP-Group/ScienceAgentBench/main/calculate_metrics.py)

DA-Code 可作为表格/Python/SQL 的第二公开评测，资源有限时只选 ScienceAgentBench，避免分散标注与复现工作。[DA-Code 官方介绍](https://da-code-bench.github.io/)

## 5. 独立评分：防止“自报完成”替代科学正确

### 5.1 主指标

对任务 i 的第 r 次运行，定义：

`S(i,r) = C(i,r) × A(i,r) × P(i,r)`

- `C`：所有预注册的关键科学断言通过，包括计算、单位、筛选范围、方法适用性与必要证据。
- `A`：规定成果已交付、可解析且内容对应当前任务；有文件但空图、错表或缺项均不通过。
- `P`：题目要求的来源定位、方法说明、代码等可追溯材料齐备。只有任务明确要求重运行时，重运行成功才是该任务的关键断言。

以 **每领域平均后再平均的任务成功率 Macro-TSR** 为主指标。先在同一任务的 3 次独立运行上取平均，再在数据来源与领域上汇总，防止某领域题目多而占据主要权重。同步提供微平均和各领域分数，不把部分完成折算成完全成功。

这个二元主指标应附带细分项：数值正确率、结构事实 F1、成果完整率和证据定位正确率。细分项用于解释错误，不能事后改变权重以改善总分。

### 5.2 次指标与计量口径

| 指标 | 定义与边界 |
| --- | --- |
| 虚假完成率 FCR | `宣称完成且独立验收失败的运行数 / 宣称完成的运行数`；同时报告其占全部运行比例、完成宣称覆盖率，防止靠全部拒答降低 FCR |
| 数值正确率 | 统一单位后满足 `abs(pred-gold) <= atol + rtol*abs(gold)` 的必需数值项比例；容差逐题预注册，不能按结果放宽 |
| 重复稳定性 | 每题 3 次成功比例及 3/3 全成功题目比例；不挑最好一次代替平均 |
| 图表语义正确率 | 原始数据一致、变量/单位/坐标/颜色编码准确、必要图例与缺测标记正确；PNG 能解码只是一项条件 |
| 可复现率 | 对要求代码的任务，在干净环境仅用原数据和交付代码重运行，通过独立答案检查的比例；同时报告相对于全部适用运行、已交付代码运行的分母 |
| 模型消耗 | 所有物理模型请求的实际输入/输出 Token；缺失 usage 的调用单列估算，报告实际用量覆盖率 |
| 成功单位成本 | 全部已启动运行的总费用 / 独立验收成功次数；没有成功则记为不可估/无穷，不能记零 |
| 时延 | 提交至最终结果可取的端到端时间、首个有效成果时间、模型调用时长、工具执行与等待时长分别记录 |
| 资源 | 沙箱/后端峰值内存、CPU 时间、逻辑读取量或实际存储 I/O、响应字节数，注明采样口径 |
| 可靠性 | 可恢复场景的恢复成功率、未知执行后的不当重放次数、故障额外调用/时间 |

成本表首先报告 Token 和硬件时间。货币换算只用实际跑测日的固定价格快照，区分缓存、输入、输出与评判费用；本方案不预估任何服务当前单价。

延迟主表不能只包含成功任务。报告全体运行在统一截止时间内的观测时长和截止率；成功任务时延作为带明确条件的副表。正常完成、失败、取消、资源截止分别保存。

“宣称完成”采用预注册的统一判定：对所有方法的最终答复盲评是否明确声称全部要求已完成，存在冲突或含糊时按统一规则仲裁；同时单列 DataSeek 的权威交付状态。不能只用 DataSeek 的结构化状态、却用其他方法的普通结束信号来比较 FCR。没有任何完成宣称时，FCR 记为未定义而非零。

### 5.3 防止评判泄漏

1. 隐藏答案、评测脚本和 gold 文件不挂载进 Agent 沙箱，也不通过工具目录暴露。
2. 原始科学数据只读；独立参考程序使用固定版本的领域库、解析器或官方工具。核心断言抽样采用第二实现/人工交叉核对，不能直接以 DataSeek 插件输出当 gold。
3. 输入只提供各方法共同可得的原始目录、原作者说明与公开领域标签。清单中的本地分析备注、预先写好的结论和 SOURCE.md 中的人工诊断需要审查，避免把验收答案当辅助材料泄漏。
4. 人工评分隐藏系统身份并随机呈现顺序；两名评分者独立判断关键语义项，分歧仲裁，报告一致性。图表抽查按预先固定的领域/成败分层抽样，不只抽 DataSeek 好案例。
5. 模型裁判可辅助定位和解释，主任务科学断言优先使用确定性评测与专家判断；不得仅让被测模型评价自身结果。

## 6. 具体实验矩阵

### E1：端到端主实验——优先级最高

运行 B0/B1/B2/B3/D 五组，盲测 144 题，每题 3 次。主模型共 **2,160 次运行**。

使用同一模型版本、共同可得输入、库版本、硬件和评测上限。先报告 D 对 B2 的主效应，再报告 D 对 B1/B3 的次比较。按领域、格式、难度及任务类型拆解，尤其比较 CSV 与 NetCDF/FITS/FASTA 等专用格式。

若某外部方法没有现成格式适配，记录覆盖率和失败原因。完整数据集上的成功率与预先定义的共同适用子集分开报告，不能运行后删除该方法失败的任务。只做接口适配仍需完成兼容性验证，当前方案不声称 B3 已经接入 DataSeek。

### E2：领域 Preset 与按需加载——2×2 因子实验

| 组别 | Preset | 工具暴露 |
| --- | --- | --- |
| P1 | general | all |
| P2 | general | on_demand |
| P3 | 预注册的领域 Preset | all |
| P4 | 同一领域 Preset | on_demand |

其他模块、模型和任务保持一致。领域标签来自各方法共同可见的预先元数据，不允许看 gold 后选 Preset。`all` 指所选 Preset 范围内的全部工具；记录初始工具数与可用工具总数，避免误解为同一个全局目录。

在运行前选定、覆盖九领域的 72 个测试任务上比较 Macro-TSR、实际总 Token、schema Token 估计、发现/加载调用次数、无效调用率和延迟。工具 schema 下降并不意味着完成任务的总 Token 必然下降。

若论文要声称“节省资源而不降低效果”，可预注册 **3 个百分点**为成功率非劣效界值，并要求配对差异置信区间下界高于 -3 个百分点；该界值是建议，需要领域评审确认和功效分析。普通显著性检验不显著不能证明非劣效。72 题可能不足以支持很窄的界值，应增加独立来源或把结论降为探索性。

### E3：自动探查与规划路径——解释任务质量来源

分别与 D 比较，不同时删除多个模块：

- **w/o 自动探查辅助**：不提供 DataSeek 生成的结构摘要，不开放 quicklook/专用概览辅助，但保留目录访问、通用 Python 和后续计算工具。Agent 仍可自行检查原始数据。检验自动探查辅助的增量收益。
- **w/o 数据集直接执行路径**：强制采用已有 Planner 路径，其余输入和工具不变。分别比较简单探查题与需要跨文件/多步计划的题；不预设直接路径总是更好。

这些开关不全是现有 Profile 参数，需要评测专用适配。关闭辅助不能删除原始文件、单位说明或参考库，否则是在改变题目信息。若路径间仍有共享探查能力，准确记录剩余能力并据此限定结论。

quicklook 为有界抽样。概览题按任务声明的抽样范围评分；要求全量统计时，抽样结果不能替代完整计算。对涉及掩膜和缺测的题目，还需检查有效零值是否被误删。

### E4：上下文与大数据——分开检验内存、传输与模型输入

**E4a 工具结果上下文：** 固定相同工具结果与证据查询，比较：

1. 截断预览，无 Spill 回读，保留相同上下文压缩；
2. Spill + 分页回读，保留相同上下文压缩；
3. Spill + 分页回读，关闭历史压缩，仍保留上下文容量检查。

将工具结果长度设置为 10 KB、100 KB、1 MB，证据位置均衡分布于开头、中间、末尾；组合 5/20/50 次历史交互。测证据检出率、上下文超限率、总模型 Token、回读次数和上下文准备耗时。相同底层证据的变体算重复测量，不算新增真实任务。

**E4b 窗口读取：** 在支持窗口的同类格式上，比较区域/分页读取与读取完整数据后计算同一结果。保持 dtype、chunk、压缩方式和查询选择率可比，设置 10 MB、100 MB、1 GB 的参考档位，实际生成范围以格式实现和硬件可承受边界为准。冻结四类格式、三档大小、两种读取方式，冷、热缓存各五次重复，分别报告，共 `4 × 3 × 2 × 2 × 5 = 240` 次确定性微测。

全量读取限于隔离评测子进程，同样设置硬件上限；超过上限记失败，不关闭解析器安全限制。测峰值内存、读取字节、CPU/墙钟时间及数值一致性。未实现窗口接口的格式不加入此组，不泛化“所有格式均支持 1 GB”。

注意：Spill 发生在工具产生结果之后，不能证明减少了工具计算阶段的内存；窗口读取的内存收益不能归因于 Spill。[现有 Spill 边界](spill-artifact-store.md)

### E5：故障、成果验收与恢复——强调可信完成

选择 12 个可复现任务，覆盖表格、图像、科学数组与多文件分析。在隔离评测环境对每个任务设置六种状态：正常、首次可修复执行失败、成果损坏/缺失、仅上传瞬时失败、执行已开始但确认丢失、续作前源数据变化。

| 组别 | 成果反馈 | 自动局部恢复 |
| --- | --- | --- |
| R0 | 不反馈成果内容诊断，独立评测器事后检查 | 关闭 |
| R1 | 保留诊断和真实状态投影 | 关闭 |
| R2 | 保留诊断和真实状态投影 | 开启现有受约束修复/恢复 |

R0/R1/R2 均保留相同只读挂载、权限、单操作超时及执行身份保护。只在评测副本中隔离反馈差异，不关闭生产保护。每格三次，共 `12 × 6 × 3 × 3 = 648` 次运行。

注入由外部评测器在规定检查点触发，使用相同故障脚本与配对条件，不能根据某方法是否接近成功临时挑时机。若方法未到达注入点，记录未暴露；主表按全部分配任务报告，恢复机制副表按实际暴露次数报告分母。

- 对可恢复故障，测恢复成功率、是否仅重传已有文件、额外调用和时间。
- 对未知执行和源数据变化，预期是停止不当重放或拒绝过期续作；这类题按正确处置计分，不能把强行继续当恢复成功。
- 如需用户点击续作，由统一评测规则在合法入口出现时模拟一次；注明这是受控干预。它与系统自行修复分开统计。
- 源数据变化仅对合成/复制的评测材料实施，绝不修改真实科研原件。

续作试验须符合当前指纹覆盖：最多 64 个路径、128 MiB 读取量等既有限制。超出限制时记录“不提供续作”的覆盖边界，不把 E4 的大文件成功推断为同样支持大文件检查点恢复。

### E6：可选探索与用户研究

**Code Mode：** 仅选五个已审阅读取工具能够完成的组合任务，对比普通逐工具调用和 Code Mode，记录外层模型调用数、内层工具调用数、总 Token、延迟与正确率。不能把一个外层调用包装多个内部调用后宣称总工具工作量下降。

**领域 SubAgent：** 在单域和跨域任务上比较开启/关闭，共用父任务的评测预算并汇总所有子请求。开启会改变规划路径，不能把全部差异归因于“多人协作”。不默认认为多 Agent 更有效。

**推荐问题：** 对同一未见数据集比较固定模板、基于名称/目录的模型推荐、实际内容驱动推荐（若待测版本支持），每组固定 Top-5。两位领域评分者盲评可回答性、数据依据、分析价值及重复性，并执行推荐题核对可回答性。推荐器不能为自己生成主实验考题；评分参考问题由独立人员编写。

**交互预览：** 若论文主要强调科研用户效率，可追加 12–18 人的探索性被试内研究，比较 DataSeek 界面与相同分析结果的文件列表/普通预览。使用匹配任务、顺序平衡，测找对变量、解释图表、发现错误的正确率、完成时间与操作数。用户数是试点建议，正式验证需功效分析；不把界面满意度替代科学正确性。

## 7. 公平性、重复与实验资源

### 7.1 共同条件

- 固定两个基础模型版本；主模型跑全体，第二模型可先在冻结的 72 题分层子集验证结论。记录供应商、模型版本、日期、采样参数、输出上限和视觉输入权限。
- 同一模型下共享温度与采样设置；可从温度 0 开始，每任务仍运行 3 次，记录可用 seed 与 run index。API 不支持 seed 时明示，不能声称完全可复现。
- 初始目录信息、原始文件、公共说明、计算库、硬件、网络权限相同。各方法的原生提示词、状态管理、重试逻辑保留并公开；“统一条件”不等于强行改成同一算法。
- 默认无人工提示、无预装标准答案、无网络搜索答案。任务若确实要求外部信息，应单列网络轨道，所有方法获得相同外部访问条件。
- 按题目随机化方法运行顺序，使用干净会话和输出目录。主模型推理尽量串行、均衡时间块；若并发，固定并发度并记录限流、排队与机器负载。
- 数据内容相同但挂载引用可以为不透明标识。实际宿主路径不进入浏览器、URL、localStorage/sessionStorage 或公开实验表。

### 7.2 评测资源上限

预实验可从每任务 **30 分钟墙钟、200k 累计 Token、64 次物理模型请求**尝试，执行到任一外部上限即结束；基础模型单次上下文和输出上限另设。它们是统一实验条件，**不是 DataSeek 当前生产限制**，正式数值由验证集确定后冻结。

所有角色、重试、修复和推荐/路由调用计入对应端到端条件。每个物理请求和重试都须在发起前预留完整输入估计与最大输出，实际 usage 返回后结算；缺失 usage 使用共同、版本化估算器并标记。若提供方实际计数高于估计，记录超额且停止后续调用，不能声称估算器保证绝不超出精确 Token 上限。评测适配器需要实现这一跨方法口径，不复用已经退出生产的旧额度配置。

主榜单采用“给定资源内的成功率”；再选冻结子集绘制 10/20/30 分钟或 50k/100k/200k Token 的成功率曲线。各预算点需独立运行或使用协议允许的严格前缀结果，不能截取未来完成的答案当较小预算的成功。

成本预算先测每种方法 10–20 题：按“预计调用数 × 平均实际成本”估算总额，并为故障与评判留余量。本轮仅设计实验，不启动付费模型跑测。

## 8. 统计分析

1. **预注册主比较和效应。** 主比较 D−B2 的 Macro-TSR，报告绝对百分点差及 95% 置信区间。可将 10 个百分点作为值得关注的设计目标，但不把它写成已达成结果。
2. **保留配对结构。** 同一来源下的任务、3 次运行、大小/故障变体存在相关性。采用按来源族分组、保留各方法配对和全部重复的 bootstrap；在可行时按领域分层抽样，建议 10,000 次重采样。不能把 432 次运行视为 432 个独立数据来源。
3. **显著性检验。** 主比较可对来源族内的方法差异作配对簇置换/符号翻转检验；次比较控制多重检验，例如 Holm 校正。普通逐题 McNemar 只适用于确有独立配对观测的分析，不能忽视同源任务聚类。
4. **时间与成本。** 报告中位数、四分位数及配对差异的区间；用全体尝试计算成功单位成本。禁止只保留成功且便宜的运行。
5. **细领域解释。** 每领域只有四个独立盲测来源时，领域差异区间可能很宽；把它们作为异质性分析，不凭一两道题宣布领域优势。
6. **缺失和故障。** 记录数据不可用、评测器缺陷、外部服务故障与方法失败。预注册可剔除条件；任何有效任务被某系统拒绝、超限或不支持，都留在主分母。评测器修复后，对受影响方法和配对任务一致重评。
7. **功效分析。** 用开发/验证数据估计来源内相关性与配对差异波动，再模拟所需独立来源数。检验效能不足时补来源或报告不确定性，不能用“p>0.05”宣称效果相同。

公开基准按各自官方评分另表呈现，不能把不同题目集合、最佳多次结果和单次平均拼成一列。

ModelTrace 字段见 [model_trace.py](../backend/app/domain/models/model_trace.py)；作业语义见 [AnalysisJob](analysis-jobs.md)。`DoneEvent` 或任务 `COMPLETED` 只代表运行结束，不能直接写入 gold-success 列。

[benchmark_context_preparation.py](../backend/scripts/benchmark_context_preparation.py) 是离线上下文准备微基准，不调用真实模型，不能代表端到端耗时、实际 Token 或科学分析正确率。

已建设独立 [benchmarks/dataseek/](../benchmarks/dataseek/README.md) 评测目录，包含任务协议、B1/D 适配器、运行器、离线评分和汇总；gold 保留在评测器私有侧。共同的逐请求资源准入、资源采样、B0/B2/B3、代码重运行和图表语义评分仍需实现，不能把当前预实验入口称为完整正式评测框架。

每次运行至少保存如下字段：

`run_id, task_id, source_family_id, domain, task_type, difficulty, method, backbone_version, code_commit, config_digest, catalog_revision, image_digest, seed_or_run_index, input_manifest_digest, start/end, stop_reason, model_call_count, actual_input/output_tokens, estimated_tokens, usage_coverage, tool_calls, peak_memory, artifact_hashes, claimed_outcome, independent_outcome, criterion_scores, fault_condition, fault_exposed`

原始输出、代码和必要的脱敏轨迹另做受控存档。现有 HMAC 和元数据 trace 不能还原完整模型提示词，不能把它们称为完整执行回放。

## 10. 实施顺序和工作量

| 阶段 | 具体交付 | 运行规模 |
| --- | --- | --- |
| 第 1 阶段：预实验 | 任务/评分协议、基线兼容性、成本与方差估计 | 18 个开发/验证候选各 2 题，先比较 B1/B2/D，各 2 次，共 216 次；这些题不计最终盲测 |
| 第 2 阶段：冻结 | 最终来源划分、144 题、专家 gold、镜像/配置/预算/统计计划 | 确定性 oracle 与评测器检查，不以模型结果选择题目 |
| 第 3 阶段：主实验 | E1 五方法结果与失败分类 | 主模型 2,160 次；第二模型 72 题子集再 1,080 次 |
| 第 4 阶段：机制解释 | E2 工具选择、E3 探查路径、E4 上下文/窗口、E5 故障 | 预算独立核算，优先与实际论文贡献最相关的组 |
| 第 5 阶段：外部验证 | ScienceAgentBench verified、复现包和论文表图 | 任务数按冻结清单；推荐 B2/B3/D，各 3 次 |

若资源有限，先完成第一阶段，再做 **E1 + E2 + E5**。只有在论文明确主张大数据/长上下文优势时，把 E4 升为必做；只有在主张交互体验或协作优势时，投入 E6。精简时削减次要研究问题，仍保留独立盲测、可靠评分和外部方法，不能仅比较 B0 下界。

实验实施涉及代码时，按仓库要求执行前端类型检查/构建、后端与沙箱测试以及 Compose 校验。2026-09-15 的预实验新增了评测代码并执行检查；通过项、跳过项和环境依赖问题见[实施报告](experiment-pilot-2026-09-15.md)。未修改生产功能、提交、推送或部署。
