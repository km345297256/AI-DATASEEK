# Harness 跟进：可靠性、执行历史与模型请求

参考上游：[deepseek-ai/deepseek-harness@0d1f50007f9bca3f52b06e1c3074fa14d5fb0720](https://github.com/deepseek-ai/deepseek-harness/tree/0d1f50007f9bca3f52b06e1c3074fa14d5fb0720)（2026-09-15）。
DataSeek 起点：`9b95762`。本轮保留 FastAPI / PlanActFlow、Cordis、Vue 界面和现有 API/SSE；不新增产品领域、不上传完整会话日志、不恢复任务累计调用/Token/时长配额。

## 第一批：正确性

- MCP 明确的 `isError` 不再被标为成功；纯文本保留字符串形式，结构化回包保留在 `data.structuredContent`，不提升为执行权限或产物凭证。
- 工具发现原子发布完整列表，最多 100 页 / 4096 个工具，拒绝重复游标及同服务器重名工具。发现时固定输入/输出契约，调用期间不隐式刷新。
- 使用 MCP SDK 的公开 typed request 接口发送一次 `tools/call`，避免其便捷调用中的动态输出校验/隐式重发现。输出校验不获取远程 `$ref`。
- HTTP/SSE 和 streamable HTTP 在发现与调用时均带配置请求头；返回值沿用凭据/主机路径隔离，并保留大结构化结果进入既有 spill 的能力。
- 二进制 MCP 内容不再通过对象 repr 混入模型上下文，而是明确说明未由文本适配器暴露；不新增媒体渲染或远程资源抓取。
- 未启动任务的创建工厂拥有准备期回滚责任：取消并注销任务、等待关闭、通过 CAS 发布/恢复会话任务指针及保存数据集选择。清理不会覆盖后继任务。
- 不调用会破坏会话复用沙箱或页面的 `destroy/on_done`。沙箱观测关联没有精确 CAS 解绑接口，本轮不盲目清空，由下次正常分配覆盖；它不是执行授权来源。

## 第二批：增量历史与图片

### 执行历史

普通新输入按其事件序号获取严格的历史前缀，执行视图包含最近对话、最新计划、数据集选择、视觉/分析结果、spill 引用和完整解包证据。当前输入只添加到任务私有深拷贝，后续已排队输入不进入本次上下文。

Mongo 会话文档中的 `execution_history_projection` 是私有可重建缓存，不进入领域 Session、浏览器响应、URL 或普通 Beanie 会话查询投影。缓存使用版本、事件序号和事件数；读取后缀前后检查前缀事件数，发现迟到提交填补序号间隙时重建。传输游标更新不改变事件语义。

- 缓存命中只读取新事件正文，按 256 条批量迭代；不会重新加载全部旧事件正文。
- 保留原有历史去重与上下文选择语义，不能将后来的重复结果误认为新的分析证据。
- 超过 4 MiB 的缓存不持久化，但完整证据仍参与处理，不以裁剪数据换取缓存命中。
- 旧混合序号历史使用原有合成顺序；安全续作仍执行原有完整历史及当前输入授权检查。
- 前缀计数仍有索引扫描成本，不能声称所有数据库工作都变为 O(1)。这是减少历史正文传输、解码和重复投影，不是删除历史。

### 模型侧图片副本

存储原图、下载和页面预览不变。模型输入单独做安全解码、方向处理、尺寸控制及 PNG 副本编码；不静默丢弃多帧科学图像的其他帧。沙箱文件下载新增向后兼容的 `max_bytes` 可选参数，有值时流式限量读取。

默认单次请求保护：最多 16 张图片，源文件 32 MiB、解码 4000 万像素、模型副本长边 2048、图片 data URL 合计 20 MiB。对应配置为 `VISION_MAX_IMAGES`、`VISION_MAX_SOURCE_BYTES`、`VISION_MAX_SOURCE_PIXELS`、`VISION_MAX_IMAGE_EDGE`、`VISION_MAX_REQUEST_BYTES`；这些不是任务累计配额。

`MODEL_REQUEST_CAPABILITIES` 是按实际 provider 和精确模型名索引的 JSON 映射，可声明 `context_tokens`、`max_output_tokens`、`vision`、`image_token_strategy`、`image_tokens`。未知模型沿用保守的通用预算，不根据名称或兼容端点猜测能力。只有已验证支持相应算法的模型才应显式启用 `deepseek_v41`；本轮不自动切换现有模型或密钥。

已存储图片在 Vision 私有记忆中保存文件引用，实际展开前重新按当前用户校验元信息和读取权限。原始 base64 不会因持久化大小限制变成不可恢复的截断字符串；活动请求与持久副本隔离。沙箱专用图片仍沿用既有有界持久化路径，不自动上传副本，也不扩大当前不支持附件的分析检查点续作范围。

单次请求先为本轮全部图片预留容量，再从新到旧展开有余量的历史图片。未展开或已不可用的历史图片在模型副本中使用明确文字占位，原私有引用和既有分析文字仍留在有界持久记忆中；本轮附件无权限或超限仍明确失败。私有文件引用不会发给模型。这样连续多轮图片分析不会把每请求保护误变成累计 16 张的任务上限。

## 第三批：重试与契约准备缓存

模型请求优先遵守合法且不超过本地单次等待上限的 `Retry-After`（秒或 HTTP 日期）；合法但超长的等待直接停止本次自动重试，不能更早重试。畸形、缺失或过期值使用有上限的指数退避及随机抖动。余额/计费耗尽、参数错误仍不重试；取消等待可中断；不重放已经执行的工具。

已绑定模型驱动追踪的请求，在已有失败追踪的私有字段中写入计划重试次数、原因和等待时间后才等待，不增加公开追踪类型或界面字段。审计失败不会导致模型请求自动再发一次。兼容调用或无法附加内部标记的第三方异常保留原异常，仅记录不含请求内容的重试日志。

工具契约准备缓存归属当前任务的工具执行管线，最多 128 项、源 Schema 合计 1 MiB，单 Schema 64 KiB。普通字典按内容指纹识别修改；Pydantic 检测模型重建及相关元数据变化，动态/无法证明稳定的 Schema 旁路。只缓存成功准备的校验器，不缓存参数、结果或错误，不全局持有动态模型类。

每次调用仍执行原有参数形状校验、Pydantic 自定义校验和默认值工厂，保留严格类型、组合 Schema、旧方言及禁止远程引用获取的边界。

沙箱全量命令在 macOS 无法收集 Linux 原生 GRIB 测试 `test_grib_window_reader.py`，故本机复测显式排除这一个文件，并在临时环境补齐 Office、质谱、Ripple 和序列测试依赖。上述 9 项失败分为：

- 4 项 GRIB 原生兼容性：缺少正式 Linux 镜像的 ecCodes 依赖/原生加载环境。
- 1 项 GDAL 共存检查：本机临时环境缺少系统 `osgeo.gdal`。
- 2 项 Office 中文字体检查：本机 LibreOffice 回退到 LinuxLibertineG，缺少正式镜像已安装的 Noto CJK 字体。
- 2 项既有 Shell 进程时序检查：主进程退出后，孙进程继承的管道使 `wait()` 延后；用例在调用 kill/replace 前即因孙进程已结束而失败。不能将它们归为本轮清理实现的回归，也不能据此断言 Linux 一定通过。

本轮没有修改前端页面、样式、沙箱代码、Compose 或端口配置。Docker daemon 当前未运行，真实 Mongo、后端/沙箱服务集成及完整 Linux 镜像验收尚未完成，不能将本机结果表述为全部部署门禁通过。

本轮不自动提交、推送或部署；后续容器更新仍仅通过既有 `./run.sh` 栈。
